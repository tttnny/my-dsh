# @lynn123411/dsh-a6api

A6API 多模型聚合站接入插件：把 A6API 聚合网关注册为 DSH 原生 LLM 提供商，模型一键同步进选择器；另有一套商户卡片界面，用来挑线路、看余额、比价格。

## 功能

- **把 A6API 的模型接进 DSH**：在「可用模型」列表点「添加到 DSH」，模型增量写入当前 Profile 的 `llm-pi-ai` 条目配置，随即出现在 DSH 对话选择器中；移除全部模型时自动移除该提供商块。
- **四个配置页面**：设置交互拆分为「可用模型」、「模型目录」、「账户资产」、「基础配置」，整体作为本插件在「插件」页里的配置页。
- **商户卡片复刻官方模型市场**：品牌图标、模型名、商户 ID、渠道说明、输入/输出/缓存读写单价、实时倍率比值、实时与 24h 与 7d 阶梯成功率点阵、延迟与缓存命中率进度条、智能标签，以及真实的固定与禁用操作；展开卡片可看详细渠道说明、近 100 次样本统计，以及官方基准价与商户实时价在各维度的对比表格。
- **给模型固定商家**：卡片一键「固定商家」/「取消固定」，把当前卡片商家绑定为该模型的优先路由；检测到模型已固定到其他商家时卡片自动切换过去，官网侧解除固定后按钮自动还原。
- **商家禁用与恢复**：卡片一键「禁用」当前商家对该模型的服务，随时「恢复」，状态以徽标展示。
- **混合价估算标注**：每张卡片价格区给出绿色「≈ ¥x.xx/亿」胶囊，按 24h 实测缓存命中率把缓存读价、输入价、输出价折算成每 1 亿 tokens 的混合人民币成本，悬停展示完整估算式；按次计费等无 token 单价的卡片不展示。
- **路由快照时效标注**：卡片右下角叠放「全网最近」与「个人最近」两行时间，日志中无路由记录的模型显示灰色「从未路由」。
- **账户资产与调用明细**：「账户资产」页实时呈现可用余额（美元及折合人民币）、历史总消耗、累计请求次数，并展示近期请求的路由明细快照（时间、模型、命中商户渠道、总耗时、Token 消耗及状态）。
- **价格波动胶囊**：标题栏余额右侧常驻「价格波动：n」胶囊，基于平台待处理的价格变动条数每 60s 轻轮询，`n>0` 时一键新标签跳转控制台，只监听不处置。
- **「模型市场」直达胶囊**：配置页标题栏与侧边栏入口弹窗的胶囊行中常驻，点击新标签直达 A6API 的模型市场。
- **侧边栏入口与卡片弹窗**：左侧边栏底部「A6api」入口（与「设置」同处），点击在屏幕正中弹出原生 Modal 商户卡片，宽 500px、高不超视口 85%，随当前会话所用模型实时切换，未使用 A6api 模型时卡片区置灰；弹窗标题栏下方常驻「价格波动」「模型市场」「配置」与「账户余额」四枚速览胶囊。
- **模型目录管理**：一键「从 A6API 获取市场模型」翻页拉取全部模型 ID，再「从 OpenRouter 一键查询」自动填充 `contextWindow / maxTokens / input`，查不到的留空可手填；行内编辑用 DSH `llm-pi-ai` 原生模型字段（`name` / `contextWindow` / `maxTokens` / `input` / `reasoningEfforts`），保存后对已启用的模型立即重写线路配置生效；支持按「可用（当前令牌白名单）/ 不可用」与「参数已填 / 未填」筛选，也可一键「清空目录」（二次确认）后重来。
- **推理档位来源有据可依**：档位只在点「从 OpenRouter 一键查询」时才去查——查到清单的按它填并记为**已确认**，上游明确没有推理能力的直接标成非推理模型，查不到明细的保持 DSH 全部思考档位（off / minimal / low / medium / high / xhigh / max）并记为**未确认**；未确认的模型在目录行与卡片上都标「档位未确认」，档位被收窄时写明「本次从 N 档变 M 档」。一键查询不覆盖手动改过的档位。
- **凭据一站式配置**：API Key / 系统访问令牌 / 账号 ID 三行字段各带明文显隐开关、已配置状态徽标与「清除」，系统访问令牌行另有就地展开的获取教程。
- **后台预热无感加载**：插件随 DSH 启动即后台预热一次完整状态，之后每 60s 静默整体刷新；服务端把余额、模型列表、日志、固定记录等上游调用并行拉取，弹窗与配置页打开时数据已就绪。「刷新列表」按钮带 `force=1` 绕过缓存立即重建最新数据。
- **接入地址与协议**：接入地址固定为官方地址（老配置里存过的非官方地址在下次写线路配置时静默改回）；模型协议在「基础配置」页三选一（OpenAI Chat / OpenAI Response / Messages），整条线路共用。

## 特性

- **原生界面形态**：「基础配置」是一列设置字段行（label / 控件 / 提示三段式，字段间 0.5px 发丝线，协议用分段控件、明文显隐用开关、清除与教程用 24px 图标按钮，底部单枚主按钮保存）；所有悬停文案统一由 `@deepseek-ai/dsh-client-ui-primitives` 的 `Tooltip` 原子承载，气泡是 DSH 原生深色样式并 `portal` 挂到 body；弹窗的居中、遮罩、Esc 与焦点回收由 `Modal` 原子负责。
- **协议与线路块的取舍**：两个 OpenAI 协议写带 `/v1` 的地址并带上「不支持开发者角色」开关（推理模型的系统提示词不被上游拒收）；Messages 写裸地址且不写该开关（宿主会自行补 `/v1/messages`，写了整条线路会被判无效）。「探测商家」跟随所选协议选端点与鉴权方式。协议存在插件自己的 `catalog.json` 里，所以一个模型都没启用时选的协议也记得住；DSH 线路块里已有 `api` 时以它为准。
- **账号 ID 自举**：平台的账户与商户接口强制要求 `New-Api-User: <账号 id>` 头，缺了一律 401，而该 id 原本只能从这些接口自身读出。系统访问令牌是 JWT 时插件就地解出 payload 里的账号 id 并一次性写回凭据；不是 JWT 时「基础配置」里的「账号 ID」输入框是唯一补位。鉴权类上游报错会翻译成可操作的中文提示，不再把「缺账号 ID」误报成「缺令牌」。
- **DSH 原生配置存储**：凭据（API Key / 系统访问令牌 / userId）存入 `~/.dsh/.credentials.yaml`（0600，环境变量优先），模型列表写入当前 Profile 的 `llm-pi-ai` 条目配置，所选协议记在插件自己的 `~/.dsh/dsh-a6api/catalog.json`；读写走 DSH 原生 `settings` / `credentials` 服务（串行写队列、schema 校验、revision 冲突校验、热发布），配置写入失败直接报错返回。旧 `dsh-a6api-config.json` 启动时自动迁移并归档为 `.bak`。
- **价格波动只监听不处置**：待处理条数按通知 `relations[].state === 'open'` 计，兼容显式 `pendingCount` 字段与 `status ∈ open/pending/effective` 的兜底形态；与余额同频每 60s 轻轮询，未配置或失效或为 `0` 时胶囊置灰不可点。
- **不内置静态模型目录**：所有参数以运行时数据为准，写入 `llm-pi-ai` 条目配置时缺省字段自动省略（由 DSH 默认值兜底）；根目录遗留的 `dsh-a6api-catalog.json` 首次加载时自动搬迁并删除。
- **服务端合并上游调用**：`/state` 把余额、模型列表、日志、固定记录等独立上游调用并行拉取（串行 5 次往返变 1 次），并保留 120s 短缓存供轮询复用。
- **形态与装配**：bundle 型插件，无自造提示层、不自行调用 LLM 运行时注册接口，也不自装 document/window 监听；装配、配置存储位置与验证见 [DETAILS.md](./DETAILS.md)。

## 安装

```bash
dsh plugin --profile web add @lynn123411/dsh-a6api
```
