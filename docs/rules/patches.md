# 本地补丁（`patches/<patch-name>/`）

每个补丁目录一份 `README.md`，**默认纯文档形式**，写明四件事：

- **目标定位方法**：如从运行中的 DSH 进程反推它实际加载的副本；
- **锚点原文**；
- **替换正文**；
- **校验步骤与回滚方式**。

确有必要才另附 `<patch-name>.sh`（须幂等：含 marker 检测与 `.bak` 备份）。

## 上游已实现同一功能时

内核升级后补丁的锚点、前提或目的可能整条消失（上游改了实现，或把修复收进官方）。此时**不要保留旧锚点与替换正文**，只在两种处置里选一种：

- **保留为「过时判定记录」**——该判定本身值得留给后来者时。只写四件事：结论（不要再打）、证据（上游实现的位置与代码原文）、复核判据（一条能重复跑的端到端命令 + 期望输出）、重建条件（出现什么变化才需要重新引入、新锚点取哪里）。判定记录不附 `.sh`。
- **直接删除补丁目录**——没有残值可留时。同时删掉根 `README.md` 本地补丁表里的那一行，并清掉其它文件里指向它的链接，不留悬空引用；那条「为什么现在不需要」的事实写进真正在维护它的地方（如消费它的 preset 的 README）。
