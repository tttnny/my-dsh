# @lynn123411/dsh-chat-translate

DeepSeek Harness Web 界面的**助手回答正文翻译**插件。它接管助手行的渲染：正文块不论源语言，一律送翻译模型加工成自然简体中文（如 `I traced the failing path to a stale lock file.` → 中文；模型写出的生硬机器腔中文同样送一遍润色——弱模型的中文恰恰最需要加工），译文按原 markdown 结构重新渲染。只翻正文：Think 卡的思考链、工具调用行、用户消息、代码块、空白块不动。**块一写完就翻**——回答还在生成时，已经写定的块立刻出中文，只有正在长的尾块保持原文。正文的排版与宿主原生完全一致，左缘不画任何标记。切换译文/原文在**贴着正文左缘的那条 10px 透明窄带**上：鼠标停在它上面出气泡，报出此刻能做的动作（读译文时「查看原文」，读原文时「查看译文」），点一下切双语，再点切回来。翻译失败时那一段保持原文、左缘留一个小 ↻（悬停报失败类别与原因，点它只重发**这一块**，等待期间原地转圈）；正文整块不响应点击——选中文字、拖选复制都不会误触。不污染会话上下文。开关有两个入口：输入框下方那一行的「译」胶囊与本插件配置页的总开关，同一个状态两处同步。配置详见 [docs/配置.md](./docs/配置.md)。

## 特性

- **接管助手行渲染**：经 keyed slot `conversation.chat.node`（key `assistant-step`，priority -1）替换宿主的助手行渲染器。正文块从数据层拿**原始 markdown**（`AssistantBlock.text`），译文同样以 markdown 交给宿主公开的基线组件 `MarkdownText`（micromark + GFM + KaTeX）重渲染——表格、列表、加粗、行内代码、公式的结构由官方渲染器保证，插件不自拼 markup。接管渲染器抛错时按框架退位规则退出该 cell，宿主原渲染器自动回位。
- **一律送译，不判源语言**：正文的每一块都进模型，包括整段中文、纯数字、纯标点的块；只有 trim 后为空的块不送译、永不标记（它没送过模型，重试也永远不会成，标记只会留下消不掉的东西）。提示词要求模型把每一段都改写成自然、地道的简体中文——意义、语气、专名、数字与术语不动，不增不删；同时要求 markdown 记号原样保留。模型判断某段已经最好而返回一模一样的文字时，同样算翻译过、同样可切换（标记传达的是「这段过了模型」）。
- **除正文外与宿主逐分支等价**：Think 折叠行（含工作细节策略下的摘要预览、Turn-process 折叠隐藏与页内搜索揭示）、连续图片组交回宿主渲染、工具调用行由宿主独立渲染、未知内容块落 JSON 展示、中断前缀行尾带「已停止」——这些 chrome 文案复用宿主 `chat` 词典，两侧逐字一致。
- **正文排版原生，左缘不画任何东西**：正文没有竖线、没有缩进——文字位置、列表与引用的缩进与宿主默认逐字一致。插件自己的可点物都落在正文**之外**：成功块是左缘一条 10px 宽的透明窄带（不占正文一个像素），失败块是一个 ↻ 按钮。窄带看不见，鼠标移上去变手型并出气泡；它没有焦点框，键盘可以 Tab 到它但没有可见标记。可翻译与不可翻译时排版完全相同。
- **切换译文/原文**：有译文的块，鼠标停在左缘那条窄带上时出气泡，文案就是此刻能做的那个动作——读译文时是「查看原文」，读原文时是「查看译文」；点一下切过去，再点切回来。切回原文后界面上不会有任何提示说「这里其实有一份译文」——那段仍然能再切回来，只是标记不变（标记只说「这段过了模型」）。
- **块一写完就翻，进视口才翻**：正文只往后追加，所以**一个新块出现，它之前的块就再也不会变**——除了正在长的尾块，每一块都在写定的那一刻送去翻译，不必等整段回答结束。行进入视口（150px 缓冲）后开始首跑：已写定的块立刻发出，之后每写定一块发一次，先回的段先出中文，按阅读顺序逐段呈现；正在长的尾块一个字都不发。历史会话因此只在真的被读到时才花请求。首跑期间界面不显示任何提示，中文回来直接替换原文。唯一让已经写定的块作废的是**上游模型自己重试**（整次尝试清空从零重来）：那时按块判断——内容一字未变的块，中文留在原地；真变了的块才重翻。
- **内容寻址的翻译池**：客户端按**原文内容**记已送达的译文，同一段原文在别处出现（同一行的另一块、另一行、另一个会话）直接复用，不再打通道；行键加文本清单判同代，换代（文本被整份重写）时旧结果作废，迟到的旧代结果丢弃。
- **失败只有两类，都保持原文**：**通道伤**（超时、断流、空返回）与**设置没配好**（缺 Key / Base URL / 模型）。失败块不进缓存、保持原文，左缘留下一个 ↻ 按钮（`dsh-ct-retry`，一直看得见，不靠悬停显形），它是失败段**唯一**的点击目标——失败段不放窄带，一段落只对应一个动作。鼠标停在 ↻ 上出气泡报出**哪一类**失败与原因（「通道伤：超时…」或「通道还没配好：先去插件页把 Key、地址、模型填齐」），读屏听到同一句——失败块自己的 `aria-label` 就是读屏唯一的通道。设置没配好时 ↻ 换上次要色（`data-unconfigured`），位置、可点性、重试行为都不变。点它**只重发这一块**（`retries`）：已经成功的块保持显示、连请求都不再发，失败的块原地转圈（同一个按钮元素，不重挂载，键盘焦点不掉），转圈期间不能重复点。一块失败不连坐：后面的块照常翻。一块里只有部分段落失败时整块保持原文，块内不出现半中半英。译文的结构漂移不是失败理由（见下条）。通道失败不自动重试：落定即终态，救活只由 ↻ 发起。失败仍在控制台留一条警告。
- **设置没配好不再无声**：以前缺 Key / Base URL / 模型时正文保持原文且界面上什么都不说——读者只会觉得插件坏了。现在同样的情形会如实报出「设置没配好」这一类，气泡和读屏都指向配置页；总开关关着仍然是纯粹的「不要翻译」，不挂任何标记。
- **结构重装配，形状问题只修不拒**：宿主先把块按 markdown 结构切段——代码围栏与纯空白段**逐字保留、永不送模型**——散文段再按输入上限切片（单段超限按空行、单行、句末切开）、相邻片段打包成一个请求（输入上限 4096 估算 token、输出上限 8192 token）。回来的译文过**形状修复**（`repairShape`）：按段落块对齐，块内结构行（记号类别、表格竖线数、链接个数、缩进代码缩进）逐一对齐并把行首前缀修回原文同款（`##`→`###`、`-`→`*`、序号、引用深度、列表缩进的漂移就此消失），散文行自由重排（软换行渲染无感），空行布局一律取原文，`[文字](URL)` 的 URL 按出现序逐字拼回。修不齐的片段自动重掷一次；仍不齐就照收模型的译文——原文一键可回，可读的译文优先于失败标记。反引号、行内代码内容一律不拦：是样式不是骨架。
- **单通道：AI 翻译（OpenAI 兼容协议）**：对接任意 OpenAI 兼容的 `chat/completions` 服务（OpenAI、DeepSeek、通义、Ollama、本地 vLLM 等）。Key / Base URL / 模型三者齐备才翻译，缺任何一项保持原文并如实报「设置没配好」，不做降级兜底。API Key 经 DSH 凭据服务读写 `~/.dsh/.credentials.yaml` 的 `TRANSLATE_API_KEY`；Base URL 与模型在本插件的配置页配置。
- **串行与超时**：同时最多一个在途请求，单次超时 `aiTimeoutMs`（默认 600000 毫秒，范围 500–900000）——每行首跑与每次手点都等到真实结果，嫌等就把超时调小。磁盘缓存池 `~/.dsh/dsh-chat-translate/cache.json`（7 天 TTL、1000 条 LRU）**按提示词修订号整体作废**：文档里登记 `rev`，换提示词语义后旧译文不会串代。
- **跟随宿主显示设置**：Think 行的折叠摘要预览跟随「工作细节」模式（读 `ui-chat` 配置的 `transcriptView`，含 legacy 取值映射）；设置缺席时按 standard。
- **DSH 原生配置接入**：配置就是本插件在 profile 里的插件配置——配置页经 `ctx.configForms` 读写条目 `dsh-chat-translate` 的 `config`，用户层落在当前 profile 的 patch；无任何自研配置文件，译文从不写回会话上下文。
- **配置页挂在宿主「插件」页**：配置卡片注册进 `plugins.bundle.config`（key 为包名 `@lynn123411/dsh-chat-translate`），路径是「插件」→本插件详情页 —— 配置直接铺在描述之下、行列表之上。页面由宿主画标题、图标与面包屑，卡片提供总开关、API Key、Base URL、模型、单次请求超时、**保存**与「测试 AI 通道」；设置页里不再有任何本插件的入口。做法与约束见仓库 `docs/rules/plugin-config-page.md`。
- **改完点保存才生效**：Base URL、模型、超时与 API Key 都是**草稿**——在页面上改它们一个字都不写盘，点一次「保存」才作为一批修订号栅栏内的写提交上去；提交成功后再自动探一次通道，把结果报在页面上（探不通不改保存结果，只说清探到了什么）。草稿不影响正在看的回答：那一段从头到尾按**已保存**的值翻完，保存之后从下一个还没翻的块开始用新值。空着保存等于清除该项（`unset`，回落到默认），超时草稿不合法时保存被拦住、草稿留着供改正。唯一即时生效的是**总开关**：它与输入框下方那颗「译」胶囊是同一个状态，胶囊没有保存按钮可点，所以拨一下就写。

## 校验

```bash
cd plugins/dsh-chat-translate && pnpm check
```

`check` 串起类型检查、构建、八份测试与产物门禁（`lib/` 不被索引跟踪）。测试覆盖：行渲染计划与宿主 `AssistantMarkdown` 的分支等价、翻译呈现单点（成功/失败两种标记、失败类别与就地补跑在途）、翻译池（流式增量送译、内容寻址复用、同代幂等、换代作废、按块补跑、逐批落定、LRU）、配置面策略跟随与**暂存式保存**（草稿不写盘、整批提交、被拒后留草稿、保存后自动探通道），以及真 react + jsdom 的渲染自检——窄带切换、拖选与点正文不误触、失败段 ↻ 是唯一可点物、补跑在途原地转圈且不重挂载（键盘焦点不掉）、两类失败各自的读屏文案。服务端半边另有结构重装配、缓存、通道契约与「设置没配好逐块如实回报」的回归；`test-host-parity.mjs` 额外盯住宿主渲染器的漂移（宿主多出一种块、或改了分组与守卫规则时当场失败，找不到 DSH 源码则明确跳过）。

## 安装

```bash
dsh plugin --profile web add @lynn123411/dsh-chat-translate
```
