# @lynn123411/dsh-chat-translate

DeepSeek Harness Web 界面的助手回答正文翻译插件：过程步骤的正文送翻译模型加工——外文译成简体中文，已经写好的中文原样抄回；结论步骤的正文按原文呈现。只翻正文，Think 卡的思考链、工具调用行、用户消息、代码块都不动。

## 概述

插件接管助手行的渲染，把每一块正文按 markdown 结构切开，散文段送翻译模型，译文按原结构重新渲染。**过程步骤翻成简体中文，结论步骤不译**：一轮回答里前面几步在干活，最后一步把结论交给读者；干活那几步的散文往往是英文，要翻；结论那一步通常是模型已经写好的中文，再送一遍只换来等待与改坏的风险。

**已写好的中文原样抄回**：过程步骤的每一块都送模型——整段中文、纯数字、纯标点的块同样照送，只有 trim 后为空的块不送译。提示词让模型把中文当抄写对象：能读通就一个字都不动，只有句子读不通时才改那几句。模型返回与原文一模一样的文字时同样算翻译过、同样可切换。

**块一写完就翻**：正文只往后追加，写定的块立刻送译，正在长的尾块保持原文；行进入视口（150px 缓冲）后开始首跑，先回的段先出中文。首跑期间界面不显示任何提示，中文回来直接替换原文。

**译文与原文一键切换**：鼠标停在正文左缘那条 10px 透明窄带上时，光标右边出一条气泡报出此刻能做的动作（读译文时「查看原文」，读原文时「查看译文」），点一下切过去，再点切回来。正文整块不响应点击，选中文字、拖选复制都不会误触。

**失败保持原文、只手点重试**：失败分两类——通道伤（超时、断流、空返回）与设置没配好（缺 Key / Base URL / 模型）。失败块保持原文，左缘留下一个 ↻ 按钮，悬停报出哪一类失败与原因；点它只重发这一块，已成功的块原地不动。失败不自动重试，一块失败不连坐。

**开关两个入口**：输入框下方那一行的「译」胶囊与本插件配置页的总开关，读写同一个 `enabled`，状态同步、拨一下即时生效。这个胶囊只在会话形态渲染，新建会话的 Hero 形态没有它。

## 安装与开关

```sh
dsh plugin --profile web add @lynn123411/dsh-chat-translate
```

这条命令把包名写进 profile 的 `dependencies` 与 `dsh.profile.bundles`，包内 `cordis.patch.yml` 随之插入一条 root loader entry：

```yaml
- insert:
    - id: dsh-chat-translate
      name: '@lynn123411/dsh-chat-translate'
```

这一条行同时承载两个半边：宿主半边在它下面注册插件本体，浏览器半边由 Web shell 按 root loader 的 enabled entry 依据 `dsh.client` 声明服务 `lib/client.js`。客户端半边声明的服务（`dsh.client.inject`）是 `@deepseek-ai/dsh-client-ui-primitives` 与 `@deepseek-ai/dsh-client-ui-plugin-manager`。

总开关关着是纯粹的「不要翻译」：正文保持原文，也不挂任何标记，窄带与 ↻ 一并消失。缺 Key / Base URL / 模型时照常可切换——缺配置只是不产生翻译，界面无特殊态。

## 配置

配置界面在宿主「插件」页本插件的详情页上，描述之下的 AI 翻译卡片里。

| 字段 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `true` | 布尔 | 总开关。与输入框下方那一行的「译」胶囊读写同一个字段，拨一下就写，不用等离开输入框。 |
| `aiTimeoutMs` | `600000` | 500–900000 | 单次请求超时（毫秒）。每行首跑与每次手点都等到真实结果，嫌等就调小。 |
| `baseUrl` | 空 | OpenAI 兼容端点 | 如 `https://api.deepseek.com/v1`。 |
| `model` | 空 | 模型名 | 如 `deepseek-chat`。 |
| `prompt` | 空 | 文本 | 拼在待译正文前面的那段指令；空着用内置默认。 |

API Key 不在配置文档里：它经 DSH 凭据服务读写 `~/.dsh/.credentials.yaml` 的 `TRANSLATE_API_KEY`（权限 0600），保存后立即生效，留空离开等于清除该键。手动编辑该文件时要么填真实 Key，要么直接删掉那一行——DSH 的凭据加载器要求 refs 键值非空，写成 `TRANSLATE_API_KEY: ""` 会让 DSH 启动失败。

所有设置都是本插件在 profile 里的插件配置：写入当前 profile 的 patch 中 `dsh-chat-translate` 条目的 `config`：

```yaml
- id: dsh-chat-translate
  name: '@lynn123411/dsh-chat-translate'
  config:
    enabled: true
    aiTimeoutMs: 600000
    baseUrl: https://api.deepseek.com/v1
    model: deepseek-chat
    prompt: 把收到的正文整理成简体中文，外文照译，中文原样抄写。
```

Base URL、模型、超时、提示词与 API Key 都是草稿：打字期间一个字都不写盘，离开那个输入框时提交上去，卡片上没有保存按钮。空着离开等于清除该项（回落到默认值）；超时草稿填了非数字时不写盘，页面报出原因、草稿留在页面上供改正。想验一次通道就点「测试 AI 通道」。

提示词是单独一张卡片，平时只读：一进页面看得到模型实际收到的那整段指令，改不动；点标题右侧「编辑」才进改写态，焦点直接落进输入框，同排多出「恢复默认」与「完成」。点「完成」（或直接离开输入框）收起改写态并把改动写盘；把框清空再点「完成」时，框里填回生效中的指令。与内置默认一字不差时同样存成空值，只读态永远显示模型实际收到的那一份。

目标语言固定为简体中文，没有配置项。

## 实现

### 装配

一条 root loader entry 承载两个半边。宿主半边注册插件本体：配置管理、翻译通道、结构重装配、缓存与 HTTP 路由。浏览器半边注册助手行渲染器、输入框下方的胶囊与插件页配置卡。

行 id 同时是配置命名空间：宿主 `Config` 与浏览器 `ctx.configForms.get('dsh-chat-translate')` 读写的是同一份值。

### 接管渲染

经 keyed slot `conversation.chat.node`（key `assistant-step`，priority -1）替换宿主的助手行渲染器。正文块从数据层拿原始 markdown（`AssistantBlock.text`），译文同样以 markdown 交给宿主公开的基线组件 `MarkdownText`（micromark + GFM + KaTeX）重渲染——表格、列表、加粗、行内代码、公式的结构由官方渲染器保证，插件不自拼 markup。接管渲染器抛错时按框架退位规则退出该 cell，宿主原渲染器自动回位。

整行接管意味着宿主两个单槽上的扩展不生效：`conversation.chat.reasoning.body`（官方 CoT 翻译注册在那里）与 `conversation.chat.message.images`（自定义图片画廊注册在那里）。Think 折叠行（含工作细节策略下的摘要预览、Turn-process 折叠隐藏与页内搜索揭示）、连续图片组、工具调用行、未知内容块、中断前缀行尾的「已停止」都由本插件自己画：图片经 `conversation.images.content` Factory 渲染，chrome 文案复用宿主 `chat` 词典。

正文排版原生：没有竖线、没有缩进、没有 padding 与 border，文字位置与列表、引用的缩进与宿主默认逐字一致。两个可点物都落在正文之外，见「切换与重试」。

### 翻译范围与时机

**过程步骤**的正文块一律送模型——「用时 XXX」大折叠块里每一步露出的正文照送。**结论步骤的正文一律不译**：整行按原文呈现，左缘什么都不出现——没有窄带、没有 ↻，也不报「设置没配好」，与总开关关着时是同一种「这里不翻译」，不是失败。

哪一步是结论，权威信号来自宿主：`TurnProcessSpec.answerStep` 取本轮最后一个 step，要求它带着 `finalNode`（消息已落定）、有读者看得见的正文、且不含 tool-call。这个字段在流式期间是 null，插件因此自己补上「还没落定」那一段的判断（`src/client/chat/conclusion.ts` 的 `isConclusionRow()`），按从严到宽分档：

| 情形 | 判定 |
| --- | --- |
| `answerStep` 有值 | 直接比 `answerStep === 本行 step` |
| 没有轮次投影（`answerStep === undefined`） | 判不了，照旧送译 |
| `answerStep` 是 null，且本行不是本轮最后一步 | 不是结论，后面还有一步要走 |
| 最后一步、还在写、块里没有 tool-call | 按结论处理：只剩正文了，先译再撤会让读者眼前的中文闪回原文 |
| 最后一步、有 tool-call | 不是结论：带工具调用的 step 永远成不了结论，当场送译 |
| 已落定（含中断）、最后一步、有正文、不含工具调用 | 是结论——宿主判据的镜像 |

`isConclusionRow()` 复刻的三条条件与宿主逐条等价，`scripts/test-host-parity.mjs` 里有一条断言钉住宿主的 `latestAnswer()` 仍是这三条，宿主改动时那条会红。

分组判据是座次传入的 `groupPart`（`response` 分组排除思考块，`reasoning` 分组只渲染思考块、不送译），流式判据是行数据的 `status === "running"`。行进入视口（150px 缓冲）后，每一块在写定的那一刻送去翻译；落定行的全部块在落定后送。

### 请求与结构重装配

宿主先按 markdown 结构切段：代码围栏与纯空白段逐字保留、永不送模型；散文段超过输入上限（4096 估算 token）时按空行、单行、句末依次切开，相邻片段打包成一个请求（输出上限 8192 token），译回后按原结构拼回——片段头尾的空行由拆下的部分补回，`[文字](URL)` 的 URL 按出现序逐字拼回。

每片段过形状修复（`repairShape`）：按段落块对齐，块内结构行（记号类别、表格竖线数、链接个数、缩进代码缩进）逐一对齐并把行首前缀修回原文同款（标题层级、列表符号、序号、引用深度、列表缩进的漂移就此消失），散文行自由重排，空行布局一律取原文。修不齐的片段自动重掷一次；仍不齐则照收模型的译文（链接数不等时不回填，其余原样）——形状问题不否决内容。

**正文少了不照收**：模型把开头那段当整段交差、后面几段一个字都不写时，收下它就是把原文那几段永久丢掉。非空行数变少的那一份按失败处理：重掷一次，第二问换成带标记的打包形状（标记把这一段框成「一整段待译内容」），仍然少就整块保持原文并留下 ↻。

同时最多一个在途请求，超时由 `aiTimeoutMs` 控制。

### 翻译池与磁盘缓存

客户端只保留一个按行登记、按**原文内容**查结果的翻译池（行以会话锚点为键，LRU 200 行）：同一段原文在别处出现直接复用，不再打通道；行键加文本清单判同代，换代（文本被整份重写）时旧结果作废，迟到的旧代结果丢弃。

唯一让已写定的块作废的是上游模型自己重试（整次尝试清空从零重来）：那时按块判断，内容一字未变的块其中文留在原地，真变了的块才重翻。

持久缓存只有磁盘池 `~/.dsh/dsh-chat-translate/cache.json`（1000 条 LRU），文档形态是 `{ rev, entries }`，其中 `rev` 登记写入它的世代——内置提示词的修订号加生效提示词与采样参数的摘要。世代与此刻生效的设置不符时整池作废重来，改提示词或换采样参数都不会让旧译文串代；读盘时按当前设置的世代比对，同一代下命中即复用。浏览器这一侧的译文池同时丢掉，否则本页里翻过的段落会一直用旧措辞的产物。已经显示在屏幕上的译文不动——下一块要翻的正文才用新指令。

### 切换与重试

正文之外有两个可点物，绝不叠在同一小片地方：

- **成功块**是宽 10px 的透明窄带（`.dsh-ct-hotspot`，`left:-10px;width:10px`，随块高铺满），整条落在正文左缘之外、不占正文一个像素、不参与排版；点它时读译文切原文、读原文切译文（键盘聚焦后 Enter/Space 同样），块与块互不影响。鼠标停在窄带上时，光标右边出一条气泡，报出此刻能做的那个动作——气泡是插件自己的浮层（`.dsh-ct-hint`，投在 `body` 下、`position: fixed`），位置由 `hint-bubble.ts` 从鼠标事件的坐标算出：默认落在光标右侧 12px、与光标同高，右边放不下就翻到光标左边，上下贴边时收回视口内；鼠标离开这条带子就收起。它外观取宿主 Tooltip 的同款令牌与尺寸，自己不接指针事件；读屏忽略它——窄带自己的 `aria-label` 才是读屏的通道。
- **失败块**是一个真的 ↻ 按钮（`.dsh-ct-retry`，官方 `IconRefreshOutlineRegular`，`left:-18px` 浮在正文左侧的空隙里），失败段不放窄带——一段落只对应一个动作。鼠标停在按钮上出 Tooltip，报哪一类失败加服务端原样带回的技术一句，读屏听到按钮 `aria-label` 上的同一句。设置没配好时按钮换次要色（`data-unconfigured`；错误红是「通道伤了」的颜色），位置、可点性与重试行为都不变。

正文整块不响应点击——选中文字、拖选复制都不会误触；在窄带上按下、往右拖进正文再松手算选字，不触发切换。悬停不改任何视觉（只有指针变手型），键盘聚焦不给任何可见标记。宿主正文列左侧恒定有 32px（侧栏嵌入 24px）内边距，因此窄带与 ↻ 落在空白里、不压任何宿主元素。

块内任一片段失败就让整块按原文渲染，块内不出现半中半英。失败结果不进缓存；通道失败不自动重试——滚动、重挂载都不会重发已落定的块，救活由点击发起：点某一块的 ↻ 只重发这一块，无限次不设额度，已成功的块原地不动（原文命中内容池的块同样直接复用，不花模型调用）。补跑在途时 ↻ 原地转圈（同一个按钮元素，只换属性，不重挂载——键盘焦点不掉），且不能重复点；补跑失败时上一次的失败结果一直挂着，↻ 因此不消失、标签也不变。

### 提示词

内置默认（`src/prompt.ts` 的 `DEFAULT_PROMPT`）的写法有几条承载行为，改文案时别删掉：

- 开头先用两个短例立住行为，示例必须排在规则前面且写成「输入/输出」的对话样式——放到后面或写成「原文/译文」，模型会把示例连同规则一起复读进译文。
- 首句说「原样抄写」而不是「翻译」或「整理」：后两类写法让模型回到改写模式，已通顺的中文会被换一套说法。
- 中文说的是「原样抄写，只有句子读不通时才改那几句」，那是它唯一被允许改动中文的入口。
- Markdown 记号只提醒一句，逐行对齐与链接回填由代码兜底。

正文分了段时，`promptFor()` 还会在生效指令末尾追加一句成段保真（「原文分几段的，译文也分几段，一段都不要少」），压住「只写开头那段、后面几段整段不写」的退化。它不进默认那一份、也不进配置页的输入框：追加与否由正文段落数决定。两层各管一段——提示词让模型一开始就写全，宿主保证即使模型还是写少了，缺段也不会被当成成品收下。

## 模型体验

翻译模型收到的是**一条 user 消息**：指令在前，空一行，待译正文在后。指令就是配置页上那段文字（空着用内置默认），正文分了段时末尾追加成段保真那一句，打包多段时再接一段标记约定（「下面每段都以单独一行标记开头……每段先原样输出那一行标记，再在下一行写这段的译文，顺序不变，段与段不要合并」）。

内置默认的指令全文：

> 例：
> 输入：The build passed.
> 输出：构建通过。
> 输入：这一版改好了。
> 输出：这一版改好了。
>
> 下面这段文字：外文译成简体中文；中文原样抄写，只有句子读不通时才改那几句。
> 保持原有的 Markdown 记号不变。只输出结果。

采样参数固定为 `temperature 0.7`、`top_p 0.6`（Hy-MT2 系列的官方推荐值）。只发标准参数：官方推荐里的 `top_k` 与 `repetition_penalty` 是 vLLM 系服务的扩展，严格的 OpenAI 兼容端点收到会直接 400，所以不随请求发出。

输入按 4096 估算 token 切片、输出上限 8192 token。同一段原文今天翻两次可能不一样，但同一段只翻一次（译文池按原文内容命中），差异只出现在不同段落之间。

缺段重掷时第二问换成带标记的打包形状：同一段原文、同一个模型就不再只写开头。

## 限制

- **目标语言固定为简体中文**，没有配置项。
- **结论步骤不译**。唯一的取舍在「最后一步、还在写、块里没有 tool-call」这一档：一个只有正文、没有 tool-call 的过程步骤会等到下一步开始时才送译——为了让结论行从第一帧起就是原文，代价是一段中文晚到。
- **宿主两个单槽上的扩展不生效**：整行接管之后，`conversation.chat.reasoning.body` 与 `conversation.chat.message.images` 上的贡献不会被调用。
- **两位以上序号的有序列表会与窄带重叠**：`10.`、`100.` 的序号往左伸出正文左缘，与那条 10px 窄带重叠，点那几像素会切换译文而不是选中文字（刻意接受，优先保证排版原生）。
- **键盘能操作但界面不加标记**：窄带与 ↻ 都可以聚焦，没有可见的焦点框。
- **失败不自动重试**，补跑只由手点发起。
- **只有一条通道**：OpenAI 兼容的 `chat/completions`。Key / Base URL / 模型三者齐备才翻译，缺任何一项保持原文并如实报「设置没配好」，不做降级兜底。
- **缓存容量有上限**：客户端译文池 200 行、磁盘池 1000 条，超出按 LRU 淘汰。

`check` 串起类型检查、构建、九份测试与产物门禁（`lib/` 不被索引跟踪）：

- `typecheck`：`src` 的类型闸门。
- `test-client-wiring.mjs`、`test-render.mjs`：按 Web shell 的方式装载浏览器 bundle，断言四处注册（助手行渲染器、胶囊、配置卡、插件页）与真 react 的渲染结果——窄带切换、拖选与点正文不误触、悬停气泡贴在光标右边并跟着走、失败段 ↻ 是唯一可点物、补跑在途原地转圈且不重挂载、两类失败各自的读屏文案。这两个脚本读 `lib/client.js`，改完 `src/` 要先 `pnpm build`。
- `test-chat-translate.mjs`、`test-regression-suite.mjs`：行渲染计划与宿主 `AssistantMarkdown` 的分支等价、翻译呈现单点（成功与失败两种标记、失败类别与就地补跑在途）。
- `test-store.mjs`：翻译池（流式增量送译、内容寻址复用、同代幂等、换代作废、换提示词时整池丢弃、按块补跑、逐批落定、LRU）。
- `test-settings-card.mjs`：配置面策略跟随与离开输入框即保存（打字期间不写盘、离开即整批提交、被拒后留草稿、并发提交共享一批写、提示词按默认/自写两态存取、清空提示词框后回到只读态会填回生效指令、拨胶囊不冲掉提示词草稿）。
- `test-channel-logic.mjs`、`test-reply-pipeline.mjs`：服务端半边的结构重装配、缓存、通道契约与「设置没配好逐块如实回报」。
- `test-host-parity.mjs`：盯住宿主渲染器的漂移（宿主多出一种块、或改了分组与守卫规则时当场失败，找不到 DSH 源码则明确跳过）。
- `assert-lib-untracked.mjs`：`lib/` 是构建镜像，不入 git。

浏览器里验收：打开一段过程步骤用英文写、结论步骤用中文写的回答，过程步骤的正文应显示中文、结论步骤保持原文；鼠标停在过程正文左缘，光标右边应出现「查看原文」，点一下换回英文、再点换回中文。把配置页的 Base URL 清空，过程正文应保持原文并在左缘出现 ↻，悬停报「设置没配好」。
