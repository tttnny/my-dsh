# 配置

> 本文档为 [@lynn123411/dsh-chat-translate](../README.md) 的配置说明。

1. **API Key**：打开「设置 - 阅读体验」，在 AI 翻译卡片中直接填写 API Key 并保存（经 DSH 凭据服务写入 `~/.dsh/.credentials.yaml` 的 `TRANSLATE_API_KEY`，权限 0600，保存后立即生效；留空保存 = 清除该键）。也可以手动编辑该文件：

   ```yaml
   refs:
     TRANSLATE_API_KEY: sk-xxx
   ```

   > ⚠️ **注意**：DSH 的凭据加载器要求 refs 键值非空。手动编辑时要么填写真实 Key，要么**直接删除该行**——不要写成 `TRANSLATE_API_KEY: ""` 这类空值，否则 DSH 启动会失败。未配置时插件不翻译，正文保持原文，不会报错。

2. **Base URL 与模型等设置**：在「设置 - 阅读体验」中填写 Base URL（如 `https://api.openai.com/v1` 或 `https://api.deepseek.com/v1`）与模型名（如 `gpt-4o-mini`、`deepseek-chat`），点击「测试 AI 通道」验证。所有设置（开关、超时、Base URL、模型）都是本插件在 profile 里的插件配置：写入当前 profile 的 patch（`~/.dsh/profiles/<profile>/cordis.patch.yml`）中 `dsh-chat-translate` 条目的 `config`。开关 `enabled` 有两个入口：设置页总开关，与聊天输入框下方那一行（composer dock）的「译」胶囊——两处读写同一个字段，状态同步；这一行只在会话形态渲染，新建会话的 Hero 形态没有它。字段都是可实时更新的，改完立即生效，可直接编辑该文件，不需重载：

   ```yaml
   - id: dsh-chat-translate
     name: '@lynn123411/dsh-chat-translate'
     config:
       enabled: true
       aiTimeoutMs: 600000
       baseUrl: https://api.deepseek.com/v1
       model: deepseek-chat
   ```

   目标语言固定为简体中文，没有配置项。

3. **翻译范围与时机**：插件接管助手行的渲染（keyed slot `conversation.chat.node` / `assistant-step`，priority -1）。正文块不论源语言一律送模型改写成自然简体中文——「用时 XXX」大折叠块里每一步露出的正文与最终汇总那一步一视同仁；整段中文同样照送（意义、术语、数字不动，顺掉机器腔）。模型返回与原文一模一样的文字时同样算翻译过：照常显示、照常可切换。trim 后为空的块不送译、不占下标、永不挂线；块内的代码围栏逐字保留、从不送模型。左缘线的色相、线型与粗细随显示态：显示译文挂 1px 主色蓝线（`--dsw-alias-state-business-primary` 65%），点回原文挂 0.5px 中性灰线（`--dsw-alias-border-l2`，备着译文、可点回），失败一律挂 1px error 色红实线（`--dsw-alias-state-error-primary` 65%——只剩通道伤一种，悬停报细节），在途挂灰线脉动（`prefers-reduced-motion` 降级为静态），没送过模型无线；线宽之差亚像素级，切换不跳字。可点的是贴着这条线的窄带而不是正文，详见下条。分组判据是座次传入的 `groupPart`（`response` 分组排除思考块，`reasoning` 分组只渲染思考块，不送译），流式判据是行数据的 `status === "running"`。流式期间整行按原文渲染；落定且该行进入视口（150px 缓冲）后，整行正文按估算 token 预算切批、逐批顺序请求，先回的段先出中文——这是每行的首跑，也是唯一自动发生的请求。

   - 不送译的内容：Think 卡的思考链正文、工具调用行、用户消息、代码块（`pre`）及其内部、空白块——这些与宿主渲染逐分支等价，接管渲染器抛错时按框架退位规则由宿主渲染器自动回位。
   - 译文用宿主基线组件 `MarkdownText` 重新渲染，表格、列表、加粗、行内代码的结构保持原样。
   - 失败只有一种（通道伤）、悬停报细节，重试归手点：块内任一片段通道失败（超时、断流、空返回）就整块按原文渲染、挂 1px error 色红实线；悬停左缘那条窄带出 Tooltip，报服务端原样带回的技术一句（如展开后的 fetch 报错、`channel timed out after 20000ms`）。**译文的结构漂移不是失败理由**——它由形状修复消化（见下条），修不齐的自动重掷一次、仍不齐则照收，永不因格式挂红线。控制台各留一条通道失败警告。失败结果不进缓存，一批失败只败在这一批；通道失败**不自动重试**——滚动、重挂载都不会重发已落定的行，救活由点击发起：点任一红线块的左缘窄带 = 整行手动补跑，无限次不设额度，已成功的块当场种回保持挂线（宿主磁盘缓存让它们秒回、不花模型调用），只有尚无译文的块重新脉动；在途窄带仍在（键盘焦点不掉）但按下去是空操作，光标也不再变手型。
   - 可点的是**贴着左缘线的那条约 17px 窄带**（线外侧 4px + 线 + 线内侧那 12px 缩进，随块高铺满），不是正文：点它时读译文切原文、读原文切译文，挂红线的块则由它补跑整行（键盘聚焦后 Enter/Space 同样），块与块互不影响；关闭总开关即全部回到原文、线全部撤下。正文整块不再响应点击——选中文字、拖选复制都不会误触；在窄带上按下、往右拖进正文再松手算选字，不触发切换。悬停不改任何视觉（鼠标移到窄带上才变手型），只有键盘聚焦时线加亮，粗细始终只表示译文/原文。挂红线的块右侧常驻一个小 ↻（官方 `IconRefreshOutlineRegular`，纯装饰不吃点击），不靠悬停显形；Tooltip 报的就是上述败因而非操作指引，屏幕阅读器读「翻译失败，点左缘那条窄带可按 Enter 重试」。
   - **缩进**：能翻译时（开关开 + Key / Base URL / 模型齐备）所有正文块统一左缩进 12px——与这块是否已挂线无关，译文落定的那一刻正文不右移、块与块左缘对齐；关掉开关或通道没配好则不缩进，排版回到宿主原样（此时切换开关整列会横移一次，是刻意的取舍）。同一行的思考行、图片组、未知块与「已停止」标记不缩进，与宿主逐字一致。

4. **请求方式**：按行请求——落定的助手行把它全部正文块一次送出。宿主先按 markdown 结构切段：代码围栏与纯空白段逐字保留、永不送模型；散文段超过输入上限（4096 估算 token）时按空行、单行、句末依次切开，相邻片段打包成一个请求（输出上限 8192 token），译回后按原结构拼回——片段头尾的空行由拆下的部分补回，`[文字](URL)` 的 URL 按出现序逐字拼回。每片段过**形状修复**（`repairShape`）：按段落块对齐，块内结构行（记号类别、表格竖线数、链接个数、缩进代码缩进）逐一对齐并把行首前缀修回原文同款（标题层级、列表符号、序号、引用深度、列表缩进的漂移就此消失），散文行自由重排（软换行渲染无感、只查整块链接总数不丢），空行布局一律取原文。修不齐的片段自动重掷一次；仍不齐则照收模型的译文（链接数不等时不回填，其余原样）——形状问题永不否决内容，红线只留给通道伤。同时最多一个在途请求，超时由 `aiTimeoutMs` 控制（默认 600000 毫秒，范围 500–900000）——每行首跑与每次手点都等到真实结果，嫌等就调小超时。客户端只保留一个按行的内存翻译池（会话锚点为键，LRU 200 行）；持久缓存只有宿主的磁盘池 `~/.dsh/dsh-chat-translate/cache.json`（1000 条、7 天 LRU），文档形态是 `{ rev, entries }`，其中 `rev` 登记写入它的提示词修订号——修订号（`src/server/prompt-revision.ts` 的 `PROMPT_REVISION`，单点登记）与实际加载的提示词不符时整池作废重来，换提示词不会让旧译文串代。

5. **通道行为**：只有一条通道——Key / Base URL / 模型三者齐备才翻译，缺任何一项都保持原文，不做降级兜底。
