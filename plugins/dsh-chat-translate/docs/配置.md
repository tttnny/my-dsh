# 配置

> 本文档为 [@lynn123411/dsh-chat-translate](../README.md) 的配置说明。

1. **API Key**：打开「插件」→ 本插件详情页（配置就在描述之下的 AI 翻译卡片里），直接填写 API Key 并保存（经 DSH 凭据服务写入 `~/.dsh/.credentials.yaml` 的 `TRANSLATE_API_KEY`，权限 0600，保存后立即生效；留空保存 = 清除该键）。也可以手动编辑该文件：

   ```yaml
   refs:
     TRANSLATE_API_KEY: sk-xxx
   ```

   > ⚠️ **注意**：DSH 的凭据加载器要求 refs 键值非空。手动编辑时要么填写真实 Key，要么**直接删除该行**——不要写成 `TRANSLATE_API_KEY: ""` 这类空值，否则 DSH 启动会失败。未配置时插件不翻译、正文保持原文，但**如实报出「设置没配好」这一类**：那一段左缘留下 ↻，气泡与读屏都指向配置页（见第 5 条）。

2. **Base URL 与模型等设置**：在本插件的配置页里填写 Base URL（如 `https://api.openai.com/v1` 或 `https://api.deepseek.com/v1`）与模型名（如 `gpt-4o-mini`、`deepseek-chat`），点击「保存」提交。**改动先停在页面上**：打字期间一个字都不写盘，点保存才作为一批修订号栅栏内的写提交；提交成功后自动探一次通道，结果报在页面上（探不通不影响保存结果，只把探到的原因写出来）。想随时单独验一次通道，点「测试 AI 通道」。所有这些设置都是本插件在 profile 里的插件配置：写入当前 profile 的 patch（`~/.dsh/profiles/<profile>/cordis.patch.yml`）中 `dsh-chat-translate` 条目的 `config`。开关 `enabled` 有两个入口：本插件配置页的总开关，与聊天输入框下方那一行（composer dock）的「译」胶囊——两处读写同一个字段，状态同步；这一行只在会话形态渲染，新建会话的 Hero 形态没有它。**总开关是唯一即时生效的项**（胶囊没有保存按钮可点，拨一下就写）；其余字段都是草稿，点保存才生效。也可直接编辑该文件，不需重载：

   ```yaml
   - id: dsh-chat-translate
     name: '@lynn123411/dsh-chat-translate'
     config:
       enabled: true
       aiTimeoutMs: 600000
       baseUrl: https://api.deepseek.com/v1
       model: deepseek-chat
   ```

   目标语言固定为简体中文，没有配置项。空着保存等于清除该项（`unset`，回落到默认值）；超时草稿填了非数字时保存被拦住，草稿留在页面上供改正。

3. **翻译范围与时机**：插件接管助手行的渲染（keyed slot `conversation.chat.node` / `assistant-step`，priority -1）。正文块不论源语言一律送模型改写成自然简体中文——「用时 XXX」大折叠块里每一步露出的正文与最终汇总那一步一视同仁；整段中文同样照送（意义、术语、数字不动，顺掉机器腔）。模型返回与原文一模一样的文字时同样算翻译过：照常显示、照常可切换。trim 后为空的块不送译、不占下标、永不标记；块内的代码围栏逐字保留、从不送模型。**正文左缘不画任何东西**：没有竖线、没有脉动、也没有缩进，正文字号、行距、列表与引用的缩进与宿主默认逐字一致。插件自己的可点物都不在正文里（窄带与 ↻ 都落在正文左缘之外），详见下条。分组判据是座次传入的 `groupPart`（`response` 分组排除思考块，`reasoning` 分组只渲染思考块，不送译），流式判据是行数据的 `status === "running"`。正文只往后追加：一个新块出现，它之前的块就再也不会变。行进入视口（150px 缓冲）后，**每一块在写定的那一刻**就送去翻译——回答还在生成时，先写定的块已经开始出中文，只有正在长的尾块保持原文。一次请求装载按估算 token 预算切批（与宿主同源），先回的段先出中文。这是每行的首跑，也是唯一自动发生的请求；首跑期间界面不显示任何提示，中文回来直接替换原文。唯一让已经写定的块作废的是上游模型自己重试（整次尝试清空从零重来）：那时按块判断，内容一字未变的块其中文留在原地，真变了的块才重翻。

   - 不送译的内容：Think 卡的思考链正文、工具调用行、用户消息、代码块（`pre`）及其内部、空白块——这些与宿主渲染逐分支等价，接管渲染器抛错时按框架退位规则由宿主渲染器自动回位。
   - 译文用宿主基线组件 `MarkdownText` 重新渲染，表格、列表、加粗、行内代码的结构保持原样。
   - 失败分两类，都保持原文、悬停报细节，重试归手点：**通道伤**（超时、断流、空返回）与**设置没配好**（缺 Key / Base URL / 模型）。块内任一片段失败就让整块按原文渲染，块内不出现半中半英；失败块左缘留下一个 ↻ 按钮（`.dsh-ct-retry`），它是失败段**唯一**的点击目标（不放窄带）。鼠标停在这个按钮上出 Tooltip，报**哪一类**失败加服务端原样带回的技术一句（如 `channel timed out after 20000ms`，或 `not configured yet: API key`），读屏听到按钮自己 `aria-label` 上的同一句——这是读屏唯一的通道。设置没配好时按钮**换次要色**（`data-unconfigured`，错误红是「通道伤了」的颜色，设置问题不是通道伤），位置、可点性与重试行为都不变（失败仍然归于一种现象：这一段没出中文，只是原因说清了）。**译文的结构漂移不是失败理由**——它由形状修复消化（见下条），修不齐的自动重掷一次、仍不齐则照收，永不因格式留下失败标记。控制台各留一条通道失败警告。失败结果不进缓存，一块失败只败在这一块；通道失败**不自动重试**——滚动、重挂载都不会重发已落定的块，救活由点击发起：点某一块的 ↻ **只重发这一块**，无限次不设额度，已成功的块原地不动、连请求都不再发（原文命中内容池的块同样直接复用，不花模型调用）。补跑在途时 ↻ **原地转圈**（同一个按钮元素，只换属性，不重挂载——键盘焦点不掉），且不能重复点；补跑失败时上一次的失败结果一直挂着，↻ 因此不消失、标签也不变。一块失败不连坐：同一行后面还没翻的块照常翻。
   - 正文之外有两个可点物，绝不叠在同一小片地方：**成功块**是**宽 10px 的透明窄带**（`.dsh-ct-hotspot`，`left:-10px;width:10px`，随块高铺满），整条落在正文左缘之外、不占正文一个像素、不参与排版；点它时读译文切原文、读原文切译文（键盘聚焦后 Enter/Space 同样），块与块互不影响。**鼠标停在窄带上时，光标旁边出气泡**，报出此刻能做的那个动作（读译文时「查看原文」，读原文时「查看译文」）——带子里有一个零尺寸锚点跟着光标走，气泡由它定位，所以提示贴着光标出现而不是钉在段落顶端；鼠标离开这条带子（哪怕是移进正文）就不再跟、也不出提示。一条看不见的带子因此也说得清自己是什么。**失败块**是一个真的 ↻ 按钮（`.dsh-ct-retry`，官方 `IconRefreshOutlineRegular`，`left:-18px` 浮在正文左侧的空隙里），失败段**不放窄带**——一段落只对应一个动作。正文整块不响应点击——选中文字、拖选复制都不会误触；在窄带上按下、往右拖进正文再松手算选字，不触发切换。悬停不改任何视觉（鼠标移到窄带或 ↻ 上才变手型），键盘聚焦不给任何可见标记（明说的取舍：键盘能操作，但界面不加标记）。关闭总开关即全部回到原文，可点物一并消失。
   - **排版**：插件不给正文加任何 padding、margin 或 border——可翻译与不可翻译时排版完全相同。两个可点物都不在正文流里：窄带与 ↻ 落在正文左缘之外。宿主正文列左侧恒定有 32px（侧栏嵌入 24px）内边距，因此它们落在空白里、不压任何宿主元素。已知的小重叠：两位以上序号的有序列表（`10.`、`100.`）的序号会往左伸出正文左缘，与那条 10px 窄带重叠——点那几像素会切换译文而不是选中文字（刻意接受，优先保证排版原生）。

4. **请求方式**：按块请求——行进入视口后，每一块在写定的那一刻（或落定行的全部块在落定后）送出去。宿主先按 markdown 结构切段：代码围栏与纯空白段逐字保留、永不送模型；散文段超过输入上限（4096 估算 token）时按空行、单行、句末依次切开，相邻片段打包成一个请求（输出上限 8192 token），译回后按原结构拼回——片段头尾的空行由拆下的部分补回，`[文字](URL)` 的 URL 按出现序逐字拼回。每片段过**形状修复**（`repairShape`）：按段落块对齐，块内结构行（记号类别、表格竖线数、链接个数、缩进代码缩进）逐一对齐并把行首前缀修回原文同款（标题层级、列表符号、序号、引用深度、列表缩进的漂移就此消失），散文行自由重排（软换行渲染无感、只查整块链接总数不丢），空行布局一律取原文。修不齐的片段自动重掷一次；仍不齐则照收模型的译文（链接数不等时不回填，其余原样）——形状问题永不否决内容，失败标记只留给「这一段没译出来」。同时最多一个在途请求，超时由 `aiTimeoutMs` 控制（默认 600000 毫秒，范围 500–900000）——每行首跑与每次手点都等到真实结果，嫌等就调小超时。客户端只保留一个按行登记、按**原文内容**查结果的翻译池（行以会话锚点为键，LRU 200 行；同一段原文在别处出现直接复用，不再打通道）；持久缓存只有宿主的磁盘池 `~/.dsh/dsh-chat-translate/cache.json`（1000 条、7 天 LRU），文档形态是 `{ rev, entries }`，其中 `rev` 登记写入它的提示词修订号——修订号（`src/server/prompt-revision.ts` 的 `PROMPT_REVISION`，单点登记）与实际加载的提示词不符时整池作废重来，换提示词不会让旧译文串代。

5. **通道行为**：只有一条通道——Key / Base URL / 模型三者齐备才翻译，缺任何一项都保持原文并如实报出「设置没配好」这一类（气泡与读屏都指向配置页），不做降级兜底。总开关关着是纯粹的「不要翻译」：正文保持原文，也不挂任何标记。
