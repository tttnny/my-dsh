# @lynn123411/dsh-subagent-judge-dispatch

派工时让一个判断模型从你自己写的任务类型清单里挑一个编号，据此改写这个子代理使用的模型与思考强度。

## 功能

- **按任务类型指派**：每次派工把派出这次活的标签和任务正文交给判断服务，由它从你的类型清单里挑一个编号，插件按这个编号对应的设置改写子代理的模型与思考强度。
- **清单由你写**：任务类型是一张表格，每一行写一段判定依据、选一个模型、选一个思考强度；模型与强度两栏各是一个下拉。模型从宿主那份「子代理可选用哪些模型」设置里读，强度从该模型自己声明的档位里读。
- **导入导出**：任务类型清单能按纯 JSON 复制走，也能粘贴回来。导入只填表格，按「保存」才写进配置。
- **完整预览**：看一眼真正会发给判断服务的整段内容，派工标签与任务正文那两处标注「派工时才填」。
- **当场试通**：判断服务的地址填完就能试一下通不通，不用等第一次派工失败。
- **密钥直接填**：判断服务要用的密钥就填在配置卡片里，存进 DSH 的凭据文件，只写不读；页面不会把它显示回来。
- **结果日志**：每个判过的子代理记一行——结果、选择、主代理、子代理、时间、耗时。结果写「类型 3」或「未判成」；选择一栏写模型与强度，悬停再补上供应商。点开一行看这次真正发给判断模型的完整内容，长内容自己折行、框里滚动。日志写进 DSH 家目录，重启之后还在；配置页里只列最近 10 条。

## 特性

- **只改两样**：只改写子代理使用的模型与思考强度，不改名字、不改标题、不动主对话，其余一概沿用 DSH 原本的派工流程。
- **判断永不打断派工**：连不上、超过 5 秒、答复对不上清单、答复为空，这四种都算判断失败；失败时一个字段都不写，子代理原样继承主代理的模型与强度，不重试。代价是每次派工最多多等 5 秒。
- **每个子代理只判一次**：判断挂在宿主公开的那条「每次模型请求」钩子上，由插件自己记住已经判过的子代理，所以一个跑十步的子代理也只问一次。
- **分节保存**：判断服务与任务类型清单各有一个保存按钮。两边改的时间不同、出错的原因也不同，合成一次保存会让一句没写完的描述挡住端点地址的修改。
- **密钥只写不读**：密钥值一交出去就不再留在页面状态里；页面只显示「已存 / 还没有」，以及一个删掉它的按钮。
- **形态与装配**：bundle 型插件，装完即用、在 profile 里不用手写补丁；装配、开发副本与验证见 [DETAILS.md](./DETAILS.md)。

## 安装

```sh
dsh plugin --profile web add @lynn123411/dsh-subagent-judge-dispatch
```
