# @lynn123411/dsh-subagent-judge-dispatch

派工时让一个判断模型从你自己写的任务类型清单里挑一个编号，据此改写这个子代理使用的模型与思考强度。

## 功能

- **按任务类型指派**：每次派工把任务文字交给判断服务，由它从你的类型清单里挑一个编号，插件按这个编号对应的设置改写子代理的模型与思考强度。
- **清单由你写**：一行一个任务类型，每行写一段描述、选一个模型、选一个思考强度。模型从宿主那份「子代理可选用哪些模型」设置里读，强度从该模型自己声明的档位里读。
- **预制词条**：研发流程常见的八类活各带一句判定依据和一句建议强度，点一下就把这句依据写进描述列，写进去之后就当是你自己写的。建议强度只是提示，模型与强度两栏不会自动填。
- **完整预览**：看一眼真正会发给判断服务的整段内容，任务文字那一处标注「派工时才填」。
- **当场试通**：判断服务的地址填完就能试一下通不通，不用等第一次派工失败。
- **结果日志**：每个判过的子代理记一行——编号、模型、强度、结果来源、时间、耗时、主会话标题、子代理描述。只活在本次运行期间，重启即清空。

## 特性

- **只改两样**：只改写子代理使用的模型与思考强度，不改名字、不改标题、不动主对话，其余一概沿用 DSH 原本的派工流程。
- **判断永不打断派工**：连不上、超过 5 秒、答复对不上清单、答复为空，这四种都算判断失败；失败时一个字段都不写，子代理原样继承主代理的模型与强度，不重试。代价是每次派工最多多等 5 秒。
- **每个子代理只判一次**：判断挂在宿主公开的那条「每次模型请求」钩子上，由插件自己记住已经判过的子代理，所以一个跑十步的子代理也只问一次。
- **密钥不落到页面**：页面里只写密钥的名字，值放在 DSH 的凭据文件里。
- **形态与装配**：bundle 型插件，装完即用、在 profile 里不用手写补丁；装配、开发副本与验证见 [DETAILS.md](./DETAILS.md)。

## 安装

```sh
dsh plugin --profile web add @lynn123411/dsh-subagent-judge-dispatch
```
