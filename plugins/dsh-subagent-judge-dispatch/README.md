# @lynn123411/dsh-subagent-judge-dispatch

派工时让一个判断模型从你自己写的任务类型清单里挑一个编号，据此改写这个子代理使用的模型与思考强度。

## 概述

每次派工，插件把派出这次活的标签与任务正文交给一个判断服务，由它从你的类型清单里挑一个编号，插件按这个编号对应的设置改写子代理的模型与思考强度。

- **清单由你写**：任务类型是一张表格，每一行写一段判定依据、选一个模型、选一个思考强度。模型从宿主那份「子代理可选用哪些模型」设置里读，强度从该模型自己声明的档位里读：档位读得到时强度栏是下拉，读不到时退回自由填写格。没填完的行、没有描述的行、描述和别的行重复的行，编号下面各有一句提示；它们照常写进配置，只是暂时不生效或判不准。每一行还有一个开关：关掉的行留在清单里，但不参与判断，也不占编号。
- **只改两样**：只改写子代理使用的模型与思考强度，不改名字、不改标题、不动主对话，其余一概沿用 DSH 原本的派工流程。
- **判断永不打断派工**：判断和路线校验共用 5 秒。判断服务不可用、答复不符合清单、校验失败或时间用完时，子代理沿用宿主已经解析好的路线。
- **导入导出**：任务类型清单与判断服务设置都能按纯 JSON 复制走，也能粘贴回来；粘进来的那一份直接替换并立即写入。判断服务那一份只含地址与判断模型，不含密钥。
- **完整预览**：看一眼真正会发给判断服务的整段内容，派工标签与任务正文那两处标注「派工时才填」。
- **当场试通**：判断服务的地址填完就能试一下通不通，不用等第一次派工失败。
- **地址自动补路径**：端点地址填到主机就行，发请求时自动补上 `/v1/systemone`；地址里已经带了 `/v1/systemone` 或 `/systemone` 就原样用，只填到 `/v1` 就只补 `/systemone`。
- **密钥直接填**：判断服务要用的密钥就填在配置卡片里，存进 DSH 的凭据文件，只写不读；页面不会把它显示回来。
- **结果日志**：记录结果、路线、时间和耗时。点开一行可看判断模型、可选类型数和输入长度。配置页显示最近 10 条，磁盘最多保留 200 条。

## 安装与开关

```sh
dsh plugin --profile web add @lynn123411/dsh-subagent-judge-dispatch
```

这条命令把包名写进 profile 的 `dependencies`，并登记进 `dsh.profile.bundles`；包内 `cordis.patch.yml` 随之插入一条根层行：

```yaml
- insert:
    - id: dsh-subagent-judge-dispatch
      name: '@lynn123411/dsh-subagent-judge-dispatch'
```

这条行同时承载两个半边：宿主半边在那条行下注册插件本体，浏览器半边由 Web shell 按 root loader 的 enabled entry 依据 `dsh.client` 声明服务 `lib/client.js`。行不写 `config`——插件页的卡片与会话菜单读写同一份插件配置。

模型与推理等级菜单中可以按会话开关判断；关闭后该会话及其嵌套子代理的派工不判断，也不记日志。插件页的配置卡片可以设置会话默认是否开启，安装后默认开启；会话自己的选择优先于默认值。「记录日志」关掉后照常判断，只是不写日志文件。整条 loader entry 关掉时插件完全不加载。任务类型清单里每一行还有自己的开关，关掉的行不参与判断，也不占编号。

宿主半边声明的服务（`inject`）：`credentials`、`sessions`；`connection` 经 `ctx.inject` 取，取不到时插件照常加载、只是没有那三条读取通道；`settings` 同样经 `ctx.inject` 取，用来声明本条目不走宿主自动生成的设置页。

客户端半边有两层声明，两层都要写（见 `docs/rules/client-wiring.md`）：

- **cordis 服务名**（`src/client/index.ts` 的 `inject`）：`slots`、`configForms`、`remote`、`remote.session`、`remote.credentials`、`locale`。`remote.session` 读模型目录，`remote.credentials` 写判断密钥。
- **插件契约包名**（`package.json` 的 `dsh.client.inject`）：`@deepseek-ai/dsh-client-locale`、`@deepseek-ai/dsh-client-ui-settings`、`@deepseek-ai/dsh-client-ui-plugin-manager`、`@deepseek-ai/dsh-client-ui-renderer`、`@deepseek-ai/dsh-client-ui-primitives`。

少声明一个不会报错，只会让插件在页面里消失。

## 配置

配置卡片住在宿主「插件」页本插件的详情页上，注册进 `plugins.bundle.config`。卡片的 key 是**包名**，卡片读写的命名空间是**本插件 Loader 行的 id**（同一个字面量 `dsh-subagent-judge-dispatch`）——两者是不同的字面量，写歪一个的症状是配置永远不出现。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | true | 没有单独选择的会话是否默认开启判断。 |
| `sessionOverrides` | `{}` | 会话 id 对应的开关选择，优先于默认值；切回默认值时通常删除该记录，若基础配置会恢复相反的值则保留明确选择。 |
| `logEnabled` | true | 判断结果写不写进日志文件。 |
| `endpointUrl` | 空 | 判断服务地址，按读者填的原样存，发请求时才补路径。 |
| `judgeModel` | 空 | 判断模型 id。 |
| `rows` | `[]` | 任务类型清单，按页面顺序；每行四个文字字段 `description`、`provider`、`model`、`effort` 与一个开关 `enabled`（缺省 true）。行没有编号字段——编号只数打开且填全的行，按数组位置从 1 连续；关掉或没填全的行不占编号，删一行、改完一行、换一个顺序，后面的自动重排。 |

字段都标了 `.volatile()`：改它们不重挂这条 loader entry，接线每次派工现读当前值。

卡片分两节：判断服务（两个开关、端点地址、判断模型、密钥、试通）与任务类型（依赖的官方配置、清单表格、导入导出、加一行），最下面是「查看完整预览」；右上角切到「日志」标签看最近 10 条判断。卡片没有保存按钮：文字格离开输入框时写一次，开关、行的增删、导入在动作发生的那一刻写。切到日志标签或离开插件页之前，还没离开输入框的那一格也会先写下去。

- **提交排队**：所有写入排成一条队列，一次只发一个。宿主按 revision 给每次写入设栅栏，两个控件接连离开时若并行发出，后一次会撞上前一次刚换掉的 revision；排队之后，后一次读到的是最新草稿，一串改动合成尽量少的写入。
- **草稿按字段保留**：宿主每次发布配置，只有读者改过、且改动与「本页上次看到的已提交值」不同的那一项才留在页面上，其余跟着宿主走。按整节保留会让一次写入把读者没碰过的字段写回去，等于撤掉别的页面刚做的改动。
- **失败就地报**：写入没落地时，那句错误出现在发起写入的那一节最后一行，两节各报各的；它留到下一次写入真的落地才消失，读者再改一下并离开输入框就会重试，不弹窗打断。密钥写失败只在密钥那一行说一次。
- **密钥只写不读**：引用名是插件自己的常量 `SUBAGENT_JUDGE_API_KEY`，不是页面填的字段——读者只要把密钥贴进来，不必知道什么是凭据引用。密钥值交给凭据服务之后立刻从页面状态里清掉；页面只显示「已存 / 还没有」。页面没有凭据通道（非回环地址）时，输入框禁用，并有一行字说明原因。
- **依赖官方配置**：在「插件 → 官方 → 子智能体」开启「允许 Agent 为子智能体选择模型」，并添加允许的提供方和模型。关闭开关、列表不可用、模型不在允许列表中，或模型不支持选定的推理等级时，子代理沿用原路线。

## 实现

### 插手位置

宿主的 `agent/created` 钩子。注册在根层上下文，每个代理创建时都会经过；插件自己用 `subagentDepth`（会话头里的 `delegationDepth` 与运行时 `options.subagentDepth` 取较大者）筛出子代理。宿主在释放子代理排队工作前 await 这个钩子，所以这里用 `agent.model.select()` 定下的路线就是它第一步用的路线；`agent/request` 不能用于这件事——那一步的选择已经定死，改提供方或模型会被宿主拒绝。一个跑十步的子代理只问一次：插件在内存里保留最近 500 个已判过的 Agent ID，插件卸载或重载后这份记录清空。

### 判断模型读到的任务

先是派出这次活的标签（`subagent/descriptor` 的 `label`，宿主用它当子会话标题），再是任务正文原文，两段之间空一行。标签只有三五个词，是派工方写的摘要；正文才是「这个活到底要做什么」。只发标签，判断只能看出个大概方向；只发正文，遇到开头是套话的任务就丢了派工方的意图。

新建时，宿主在 `agent/created` 监听器返回后才投递初始任务。插件只在直接父会话当前步骤查找尚未结束的 `subagent` 或 `subagent_fork` 调用，要求派工描述与子代理 `subagent/descriptor` 的标签唯一匹配。直接调用和 `run_code` 内部调用分别对应 `tool/call` 与 `tool/ptc-dispatch-start`。找不到唯一匹配时，子代理沿用原路线。

恢复时，插件通过父会话的 `subagent/catalog` 定位本子代理的原始派工，并核对初始任务。初始任务的来源是直接父会话发出的 `agent-message`，可以出现在收件箱的 `agent/inbox/spliced` 中，也可以已经写成 `user/message`。取正文时去掉开头的发件人提示和末尾的回报说明。找不到原始派工的恢复会话沿用原路线。

只读子代理自己的事件：`ownEvents()`（或 `snapshotEvents(inheritedEventCount)`）是子代理自己产生的那一段。不能从日志开头读——叉出来的子代理，日志前缀是父代理已完成的回合，从开头读会把祖先的标签和父对话的第一条消息送给判断模型。

发给判断服务的长任务保留开头 1400 字和结尾 400 字，中间标明省略字数。

### 判断协议

`POST` 到页面填的地址自动补上路径之后的完整地址，请求体 `{ model, state: { message }, questions }`；`questions` 只有一个 `task_type`，类型是 `choice`，`criteria` 就是交给判断模型的那份清单（键是编号、值是你写的描述）：只含打开且填全的行，编号按清单顺序从 1 连续，没有缺号。答复取被选中选项的编号。

预览、真正发出的请求与答复匹配读的是同一份编号：关掉或没填全的行在这三处都不出现，所以预览里是编号 2 的那一行，就是答复「2」会选中的那一行。

提供方、模型和推理等级一次写入。派工调用显式指定路线，或子会话已经记录了模型选择或使用记录时，插件保留原路线。写入前，插件查宿主当前的子代理允许列表，并用 `llm.resolveCallConfig()` 校验这组提供方、模型和推理等级。模型校验返回后再核对允许列表，避免应用在校验期间撤销的路线。

判断失败或预检失败时，子代理沿用宿主已解析好的路线。

端点地址补全：页面只存读者填的那一段地址，真正请求的地址在发请求时算出来——已经以 `/v1/systemone` 或 `/systemone` 结尾就原样用，只填到 `/v1` 就补 `/systemone`，更短的补 `/v1/systemone`。地址与模型两格都不预填值，占位提示给出例子。

试通不依赖类型清单：连通性检查问的是「这个地址与模型能不能答」，所以它自己带一个选项发给判断服务，与读者写没写类型无关——清单是判断时才需要的输入，拿它当能不能测的前提，会让空清单的读者以为服务坏了。返回的原因是连通性本身：`unconfigured`（地址或模型没填）、`unreachable`、`timeout`、`unmatched`。

### 日志

判断日志写在 `~/.dsh/dsh-subagent-judge-dispatch/judgements.json`（跟随 `DSH_HOME`）。多个进程在同一个文件锁内读取并合并最新记录，再原子替换文件。

「选择」列显示模型和推理等级，悬停可以查看提供方。「未判成」结果的悬停提示说明失败原因。点开日志行可看当次请求的数值和模型信息。日志不保存任务正文、派工标签、会话标题或判断条件。日志页的「分析判断结果」可复制一段统计最近 100 条日志的请求。

### 导入导出

任务类型清单导出成 `[{ description, provider, model, effort }]`，不带编号——编号是按位置排的，写出去会让读者以为它是设置的一部分。判断服务设置导出成 `{ endpointUrl, judgeModel }`，不含密钥：密钥只写不读，复制走的文本里不该有它。

导入是一个只收粘贴的弹窗：不读文件、不联网，粘进来的 JSON 先过形状检查（清单必须是数组、每条是对象、四个字段是文字、不能有整条全空的行；设置必须是对象、两个文字字段、地址与模型不能都空着），合格就整份替换并立即写入——弹窗里那颗按钮本身就是确认。三种坏输入（不是 JSON、形状不对、空清单或空设置）各自说一句不同的话，不合并成「格式有误」。

### 卡片布局

两节的标题行右端各排一组动作。任务类型那一节是「导入、导出、加一行」：前两件是同一件事的两个方向，加一行是往表尾续一条，放在最后不打断这一对；行上只剩「删掉」——说明放不下时点进格子就能左右滚动看全并编辑。判断服务那一节是「导入、导出、试通」：前两件是这一节设置的两个方向，试通问一句能不能用，排在最后；试通不落盘，读的是已落地的值，所以写入还在路上时先不给按。两节的导入导出共用同一个粘贴弹窗，标题、说明与三种坏输入的话各用各的。

行的问题写在编号列下方：不生效（模型路由没填全）、没有描述、描述和别的行重复，各占一句。它们都不拦写：读者可能正打到一半，而服务端本来就跳过不可用的行。

预览单独排在卡片最下面：它同时读判断模型与整份类型清单，哪一节都不独占。这一排按卡片宽度靠右对齐。

## 模型体验

判断服务收到的请求体是 `{ model, state: { message }, questions }`：`model` 是页面填的判断模型，`message` 是「派工标签 + 空行 + 任务正文」（长任务按头尾截），`questions` 只有一道 `task_type` 选择题，`criteria` 是类型清单的编号到描述的映射。判断模型只回答一个编号。

子代理自己看到的东西里，只有模型与思考强度被改写；名字、标题、主对话都不动。判断失败时子代理按宿主原本解析好的路线跑，与没装这个插件时一样。

## 限制

- 判断服务和宿主路线校验共用 5 秒，时间用完时沿用原路线。
- 编号按位置算：关掉一行、填完一行或换一个顺序，后面的编号都会重排；日志里早先记下的编号可能因此指向另一行。
- 每个子代理只判一次，插件卸载或重载后这份记录清空。
- 宿主未开启子代理模型选择时，派工沿用宿主原路线。
- 日志文件留最近 200 条，配置页只列最近 10 条。
- 判断协议里的截断标记与失败原因用英文，不随界面语言变。
- 任务类型的模型选项来自官方子代理设置中的允许列表。

## 验证

```sh
cd plugins/dsh-subagent-judge-dispatch && pnpm check
```

`check` = `typecheck` + `build` + 五个自检 + `assert:lib-untracked`：

- **`scripts/test-decision.mjs`** 直接验证判断请求、答复匹配、超时、类型编号与日志保留。用四个进程同时追加日志，核对磁盘保留完整的最新 200 条。
- **`scripts/smoke-host.mjs`** 用 Cordis `Context` 验证 `agent/created` 的派工关联、原路线保留、实时允许名单、推理等级校验、共享时限与无任务正文的日志。覆盖直接调用和程序化派工、任务还在收件箱或已落盘的恢复、兄弟会话消息、无关调用、已结束调用、重复描述和明确选择。
- **`scripts/smoke-client.mjs`** 按 Web shell 的方式装载 `lib/client.js`（`window.__ModuleLoader__.load` 桩件），喂假 cordis 服务：断言卡片注册进 `plugins.bundle.config`、key 是包名、走 `slots.inject`、读本插件自己的命名空间与宿主那份「子代理可选用哪些模型」设置、以宿主在服务本条目为挂载条件、样式表在 `apply()` 追加一次且没写死色值，以及 zh/en 键集一致。它的守卫带反例断言（「守卫拒绝未声明的服务读取」必须抛）。
- **`scripts/test-card.mjs`** 打的是 `src/`，守配置卡片这层状态机：文字格只在提交时写且只写改过的那一项、开关与行的增删当场写、连续两次提交合并成一次写、没填完的行照常写入而页面只在行上提示、宿主回 `false` 算没写进去、密钥跟着判断服务那次提交一起写且写的是固定引用名、密钥值从不进页面状态、草稿按字段保留，「选择」一列只写模型与强度、悬停才带上供应商，清单与判断服务设置各自的 JSON 导出与导入认什么、拒什么。
