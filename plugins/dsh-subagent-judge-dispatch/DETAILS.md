# @lynn123411/dsh-subagent-judge-dispatch 详情

> 本文档是 [README.md](./README.md) 的补充：装配形态、开发副本与验证。

## 装配形态

装进 profile 一条命令即可，在 profile 里不用手写任何补丁：

```bash
dsh plugin --profile web add @lynn123411/dsh-subagent-judge-dispatch
```

这条命令把包名写进 profile 的 `dependencies`，并登记进 `dsh.profile.bundles`；包内 `cordis.patch.yml` 随之插入一条根层行：

```yaml
- insert:
    - id: dsh-subagent-judge-dispatch
      name: '@lynn123411/dsh-subagent-judge-dispatch'
```

这条行同时承载两个半边：宿主半边在那条行下注册插件本体，浏览器半边由 Web shell 按 root loader 的 enabled entry 依据 `dsh.client` 声明服务 `lib/client.js`。行不写 `config`——配置一律经插件页的卡片读写，避免出现第二处真相。

宿主半边声明的服务（`inject`）：`credentials`、`sessions`、`sessionTitle`；`connection` 经 `ctx.inject` 取，取不到时插件照常加载、只是没有那三条读取通道；`settings` 同样经 `ctx.inject` 取，用来声明本条目不走宿主自动生成的设置页。

客户端半边有两层声明，两层都要写（见 `docs/rules/client-wiring.md`）：

- **cordis 服务名**（`src/client/index.ts` 的 `inject`）：`slots`、`configForms`、`remote`、`remote.session`、`remote.credentials`、`locale`。`remote.session` 读模型目录，`remote.credentials` 写判断密钥。
- **插件契约包名**（`package.json` 的 `dsh.client.inject`）：`@deepseek-ai/dsh-client-locale`、`@deepseek-ai/dsh-client-ui-settings`、`@deepseek-ai/dsh-client-ui-plugin-manager`、`@deepseek-ai/dsh-client-ui-renderer`、`@deepseek-ai/dsh-client-ui-primitives`。

少声明一个不会报错，只会让插件在页面里消失。

配置卡片的 key 是**包名**，卡片读写的命名空间是**本插件 Loader 行的 id**（同一个字面量 `dsh-subagent-judge-dispatch`）——两者是不同的字面量，写歪一个的症状是配置永远不出现。

## 判断与改写

- **插手位置**：宿主的 `agent/created` 钩子。注册在根层上下文，每个代理创建时都会经过；插件自己用 `subagentDepth`（会话头里的 `delegationDepth` 与运行时 `options.subagentDepth` 取较大者）筛出子代理。宿主在释放子代理排队工作前 await 这个钩子，所以这里用 `agent.model.select()` 定下的路线就是它第一步用的路线；`agent/request` 不能用于这件事——那一步的选择已经定死，改提供方或模型会被宿主拒绝；0.2.2 起该钩子已标为 deprecated，官方迁移方向正是 `agent.model.select()`。
- **判断次数**：按子代理 id 记住已判过的，一个跑十步的子代理只问一次。
- **判断模型读到的任务**：先是派出这次活的标签（`subagent/descriptor` 的 `label`，宿主用它当子会话标题），再是任务正文原文，两段之间空一行。标签只有三五个词，是派工方写的摘要；正文才是「这个活到底要做什么」。只发标签，判断只能看出个大概方向；只发正文，遇到开头是套话的任务就丢了派工方的意图。
- **任务正文怎么取**：新建的子代理从父会话刚记录的派工调用里取，恢复或继续的子代理从自己那条 `source.kind === 'user'` 的消息里取。新建那一刻子代理自己的日志里还没有任务——宿主在创建监听器返回后才把 prompt 投进它的收件箱。父会话的派工调用有两种记录形状，两种都要认：模型直接调工具留 `tool/call`（`arguments` 是模型产出的 JSON 字符串），在 `run_code` 程序里调工具留 `tool/ptc-dispatch-start`（`arguments` 已经是对象）。两种事件都在调用开始时落盘、早于工具本体执行，所以创建子代理时都读得到；按派工方写的描述（与子代理 `subagent/descriptor` 的 `label` 同一个字符串）认出是哪一次调用，对不上时取最新一条带 prompt 的。子代理自己的消息按 `source.kind === 'user'` 认：用户角色不等于任务——工作目录提示、工作区指令、运行时快照、技能清单、时间快照都写成用户消息，按来源筛才分得开；这条消息在日志里以两种形状出现，收件箱里的待办（`agent/inbox/spliced` 的 `inserted`）与认领后写成的 `user/message`，两种都认。宿主的返回指引（「你的父代理 id 是……完事用 `send_message` 回报」）是那条消息末尾追加的一个文本块，讲的是怎么交作业，不算任务，取正文时整块去掉。
- **只读子代理自己的事件**：`ownEvents()`（或 `snapshotEvents(inheritedEventCount)`）是子代理自己产生的那一段。**不能从日志开头读**：叉出来的子代理，日志前缀是父代理已完成的回合，从开头读会把祖先的标签和父对话的第一条消息送给判断模型。
- **长任务按头尾截**：正文留开头 1400 字与结尾 400 字，中间省掉多少字写在省略号里（`… (N characters omitted) …`）。补充要求常写在末尾，所以留尾不留中；把省掉的字数写出来，读者看日志里那段请求才分得清「截断了」和「本来就这么短」。这句标记用英文，是判断协议本身的语言——中文写在英文任务里像任务的一部分，读者与判断模型都会读岔。
- **日志落盘**：判断日志写在 `~/.dsh/dsh-subagent-judge-dispatch/judgements.json`（跟随 `DSH_HOME`），文件留最近 200 条，配置页只列最近 10 条——页面是看一眼刚发生什么的地方，不是日志查看器。连续追加合并成一次写入，先写临时文件再改名，进程崩了也不会留下半份文档；一条记录的字段缺了，留住它带着的那部分，不连累整份文件。
- **日志那一栏与判断输入分开算**：表格「子代理」一栏只放派工标签（没有标签时退回正文开头，截到 60 字），不把判断模型读过的那一整段塞回去——那一整段在同一行的弹窗里能看到。
- **判断协议**：`POST` 到页面填的地址自动补上路径之后的完整地址，请求体 `{ model, state: { message }, questions }`；`questions` 只有一个 `task_type`，类型是 `choice`，`criteria` 就是你的类型清单（键是编号、值是你写的描述），答复取被选中选项的编号。
- **写入铁律**：模型、强度、提供方三项一起写。`resolveChildAgentOptions` 在「换了模型但没给强度」时会删掉继承来的强度，所以三项必须同进同出。
- **兜底**：任何失败都一个字段都不写，把宿主解析好的那个调用配置按身份原样退回——不是「把主代理的值再写一遍」，而是根本不碰它。这是 `decideRewrite` 返回 `none`、`applyDecision` 原样返回入参所保证的。

## 配置卡片

- **试通不依赖类型清单**：连通性检查问的是「这个地址与模型能不能答」，所以它自己带一个选项发给判断服务，与读者写没写类型无关——清单是判断时才需要的输入，拿它当能不能测的前提，会让空清单的读者以为服务坏了。返回的原因是连通性本身：`unconfigured`（地址或模型没填）、`unreachable`、`timeout`、`unmatched`。
- **端点地址自动补路径**：页面只存读者填的那一段地址，真正请求的地址在发请求时算出来——已经以 `/v1/systemone` 或 `/systemone` 结尾就原样用，只填到 `/v1` 就补 `/systemone`，更短的补 `/v1/systemone`。地址与模型两格都不预填值，占位提示给出例子。
- **没有保存按钮**：每个控件按自己的时机写。文字格（端点、判断模型、类型行的说明与强度）在离开输入框时写一次，打字期间只改草稿；两个开关、行的增删、导入都在动作发生的那一刻写。切到日志标签或离开插件页之前，还没离开输入框的那一格也会先写下去。
- **提交排队**：所有写入排成一条队列，一次只发一个。宿主按 revision 给每次写入设栅栏，两个控件接连离开时若并行发出，后一次会撞上前一次刚换掉的 revision；排队之后，后一次读到的是最新草稿，一串改动合成尽量少的写入。
- **密钥跟着判断服务那一次提交走**：密钥格离开输入框或按回车时写。密钥先写，再写设置；密钥没写进去就不再动设置。设置被宿主拒绝（共享配置表单 resolve `false` 是拒绝，不是异常）时页面必须报没写进去，不能显示成已保存。
- **草稿按字段保留**：宿主每次发布配置，只有读者改过、且改动与「本页上次看到的已提交值」不同的那一项才留在页面上，其余跟着宿主走。按整节保留会让一次写入把读者没碰过的字段写回去，等于撤掉别的页面刚做的改动。
- **失败就地报**：写入没落地时，那句错误出现在发起写入的那一节最后一行，两节各报各的；它留到下一次写入真的落地才消失，读者再改一下并离开输入框就会重试，不弹窗打断。密钥写失败只在密钥那一行说一次。
- **试通在判断服务那一节的标题行右端**：试通不落盘（它只是问一句），读的是已落地的值，所以写入还在路上时先不给按。
- **导入、导出、加一行排在任务类型那一节的标题行右端**：三件都是整张表的动作，顺序固定为「导入、导出、加一行」：前两件是同一件事的两个方向，加一行是往表尾续一条，放在最后不打断这一对。行上只剩「删掉」——说明放不下时点进格子就能左右滚动看全并编辑。
- **判断服务那一节的标题行右端是「导入、导出、试通」**：前两件是这一节设置的两个方向，试通问一句能不能用，排在最后。两节的导入导出共用同一个粘贴弹窗，标题、说明与三种坏输入的话各用各的。
- **依赖官方配置**：任务类型能选什么由宿主那份「允许 Agent 为子智能体选择模型」决定，所以这一节顶部写明这件事，并给一个「去设置」入口。宿主没有「按 id 打开某张官方卡片」的跨插件调用，跳转分两步：`pluginNavigation.openList()` 回到插件页列表，再按下 `[data-plugin-item="subagent"]` 那张卡片——第二步用的是插件页公开的 `data-plugin-item` 属性，不碰它的私有 store；页面没有 `pluginNavigation` 时入口不显示。
- **行的问题写在编号列下方**：不生效（模型路由没填全）、没有描述、描述和别的行重复，各占一句。它们都不拦写：读者可能正打到一半，而服务端本来就跳过不可用的行。
- **预览单独排在卡片最下面**：它同时读判断模型与整份类型清单，哪一节都不独占。这一排按卡片宽度靠右对齐。
- **判断日志是一张六列表**：结果（`类型 3` / `未判成`）、选择（`模型 · 强度`，悬停补上供应商）、主代理、子代理、时间、耗时。结果在最左，读者扫一眼先看「判成了没有」；选择一栏只写各条之间真正不同的两样，供应商几乎每行都一样，悬停才把整段路 `供应商 · 模型 · 强度` 写出来。没判成的原因同样不在格子里展开，悬停才说——那一列宽度是给编号留的。放不下的格子截断，气泡用宿主的 `Tooltip`（原生 `title` 键盘够不到）。
- **点一行看的是这段提示词**：弹窗里只有这次真正发给判断模型的请求体，任务文字也在里面。正文按字符折行，不给长行留横向滚动；高度超出一屏就在框里竖向滚动，滚动条的深浅跟着弹窗这层表面走。结果、选择、主代理这几项行上已经有了，弹窗不再各列一遍。这条请求体由发出请求的那一处格式化后原样存进日志，页面没有第二次拼装的机会——`scripts/smoke-host.mjs` 断言日志里那一段与发出去的请求体同值。
- **导入导出走纯文本**：任务类型清单导出成 `[{ description, provider, model, effort }]`，不带编号——编号是按位置排的，写出去会让读者以为它是设置的一部分。判断服务设置导出成 `{ endpointUrl, judgeModel }`，不含密钥：密钥只写不读，复制走的文本里不该有它。导入是一个只收粘贴的弹窗：不读文件、不联网，粘进来的 JSON 先过形状检查（清单必须是数组、每条是对象、四个字段是文字、不能有整条全空的行；设置必须是对象、两个文字字段、地址与模型不能都空着），合格就整份替换并立即写入——弹窗里那颗按钮本身就是确认。三种坏输入（不是 JSON、形状不对、空清单或空设置）各自说一句不同的话，不合并成「格式有误」。
- **密钥固定引用**：引用名是插件自己的常量 `SUBAGENT_JUDGE_API_KEY`，不是页面填的字段——读者只要把密钥贴进来，不必知道什么是凭据引用。密钥值交给凭据服务之后立刻从页面状态里清掉，`scripts/test-card.mjs` 有一条断言守着它不出现在状态里。密钥格与上面几格同宽；页面没有凭据通道（非回环地址）时，输入框禁用，并有一行字说明原因。

## 开发副本

运行副本用 `link:` 连到本仓库目录，改完即生效（细则见仓库 `docs/rules/dev-copy.md`）：

```bash
cd ~/.dsh/profiles/web && pnpm add "link:<my-dsh 绝对路径>/plugins/dsh-subagent-judge-dispatch" --offline
cd <my-dsh 绝对路径>/plugins/dsh-subagent-judge-dispatch && pnpm install && pnpm build
```

客户端半边改完刷新页面即生效，必要时强制刷新一次；宿主半边改完要触发一次 profile 重新组合——在插件页或 `plugin_manager` 里把本插件关一次再开一次，不必重启进程。

## 验证

在包目录跑一条链：

```bash
cd plugins/dsh-subagent-judge-dispatch && pnpm check
```

`check` = `typecheck` + `build` + 五个自检 + `assert:lib-untracked`：

- **`scripts/test-decision.mjs`** 打的是 `src/`（Node 直接跑 `.ts`），守判断与改写这条纯逻辑：失败时**按身份**退回同一个对象（不是深比较——深比较会放过「复制一份再写回原值」这种仍然算覆盖的写法）、三项同写、残缺行不生效、答复读取的三种形状与七种空答复、四种失败原因各自的归类、超时不重试、日志文件留 200 条、页面只取最近 10 条、换一个 LogStore 实例也读得回来、文件缺失或残缺都不抛、读出来是副本，编号按位置从 1 连着。它还守判断模型读到的输入：标签在前正文在后、没标签时只发正文、两样都没有时输入为空、短任务一字不动、长任务留头尾并写明省掉多少字、刚好到上限的不算截断。端点地址的补全也在这里守：没带路径时补 `/v1/systemone`、已经带了两种路径之一就原样用、只填到 `/v1` 时只补 `/systemone`、去掉末尾斜杠、没有地址就没有请求地址。另有一条守「判断带回的提示词就是发出去的那一段」：成功、失败、没发出请求三种情形各一条。
- **`scripts/smoke-host.mjs`** 起真 cordis `Context`，把 `agent/created` 钩子按宿主的方式跑一遍（判定后断言 `agent.model.select()` 收到了什么；判定没成时断言一次都没调）：主代理不被判断、同一子代理只判一次、两个开关各自的短路、发送出去的请求体形状、判断输入是标签加正文两段、正文按 `source.kind` 取（工作目录提示不算任务）、新建子代理时从父会话刚记录的派工调用里按标签取正文（模型直接调用与 `run_code` 里的程序化调用两种记录形状各一组用例）、派工消息还在收件箱里与已经落盘成 `user/message` 两种形状都读得到、宿主追加的返回指引不送进去、长任务留头尾且写明省掉多少字、没有描述时取任务正文、叉出来的子代理只读自己的事件、日志的子代理一栏只写标签、判断过的记忆有上限。它的夹具照真实日志的形状搭：先是 `working-directory` 的通知，再是收件箱里那份待办；两种形状各有一组用例，一组把消息留在收件箱，一组用落盘后的 `user/message`。它另起一个挂着 `connection` 的实例，从日志路由读回那一行，断言 `prompt` 与真正发出去的请求体同值——判断成功与判断失败各一条。
- **`scripts/smoke-client.mjs`** 按 Web shell 的方式装载 `lib/client.js`（`window.__ModuleLoader__.load` 桩件），喂假 cordis 服务：断言卡片注册进 `plugins.bundle.config`、key 是包名、走 `slots.inject`、读本插件自己的命名空间与宿主那份「子代理可选用哪些模型」设置、以宿主在服务本条目为挂载条件、样式表在 `apply()` 追加一次且没写死色值，以及 zh/en 键集一致。它的守卫带反例断言（「守卫拒绝未声明的服务读取」必须抛），否则那一串绿灯是假的。

- **`scripts/test-card.mjs`** 打的是 `src/`，守配置卡片这层状态机：文字格只在提交时写且只写改过的那一项、开关与行的增删当场写、连续两次提交合并成一次写、没填完的行照常写入而页面只在行上提示、宿主回 `false` 算没写进去、密钥跟着判断服务那次提交一起写且写的是固定引用名、密钥值从不进页面状态、草稿按字段保留（宿主改了一项而我在改另一项时，提交只写我改的那一项），「选择」一列只写模型与强度、悬停才带上供应商且两条路都不留悬空的分隔点，清单与判断服务设置各自的 JSON 导出与导入认什么、拒什么（判断服务那一份不带密钥，缺字段当空串），以及官方配置入口的有无与调用。
- **`scripts/test-render.mjs`** 用真 react 把卡片画进 jsdom：没有保存按钮，判断服务那一节的标题行按「导入、导出、试通」排、任务类型那一节的标题行按「导入、导出、加一行」排，行上只剩「删掉」，预览单独在卡片最下面那条栏里；任务类型那一节写明依赖的官方配置，点入口先回插件页列表、再按下那张官方卡片；文字格离开才写、写的是这一格的新值，行的问题写在编号列下方；日志表是六列且顺序固定，结果写「类型 3」/「未判成」，选择格只写模型与强度、供应商在悬停气泡里，导出把清单按纯 JSON 写进剪贴板、导入直接替换并立即写入且三种坏输入各报各的话，没判成的原因挂在宿主的 `Tooltip` 上而不是原生 `title`，弹窗里只有那段提示词且不把行上的栏目再列一遍。`ui-primitives` 走替身（真组件是浏览器 ESM、带 `.css` 导入，Node 里跑不起来），所以它验的是本插件的视图结构，外观与浮层定位要在真浏览器里看。

`lib/` 是构建镜像，`assert:lib-untracked` 判它没被 git 跟踪。
