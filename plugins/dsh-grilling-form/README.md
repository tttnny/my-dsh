# @lynn123411/dsh-grilling-form

grilling 轮的逐题盘问工具：把整轮问题作为一张**可交互表单**投在对话流的**轮次尾部**（没有折叠行、没有卡片壳，跟正文同处一层）投出即结束本轮；用户在表单里勾选、自填，点表单底部的「导入输入框」写进**原生输入框草稿**，再按原生发送键发出，作答随后作为**下一条用户消息**到达。它不出文本、不阻塞、不接管输入框，与原生 `ask_user_question`（[`@deepseek-ai/dsh-tool-ask-user`](https://www.npmjs.com/package/@deepseek-ai/dsh-tool-ask-user)）是两件事：原生那条在输入框上方接管作答面板、阻塞等答案，留给一次简单确认；本插件只负责 grilling 轮的逐题盘问。

## 功能

- **`grilling_form` 工具**：一次调用校验入参、标记本轮结束（`exec.concludeTurn()`）、返回 `{ pending: true, message }`，让模型知道表单已展示、答案会晚到；投出即结束，不等待答案、不接管输入框。入参不合格则返回 `rejected` + `violations` 且**不标记结束**，模型可在同一轮改完重调。
- **三种题型**：每题必写 `type`——`single`（单选，一题至多留一项）、`multi`（多选，可多可少可不选）、`free`（自由题，一个打字框）。单选与多选至少给一个选项并另有一个自填框，自由题一个选项都不许给。
- **推荐标记与推荐项默认勾上**：模型把推荐写成 `description` 末尾的「；推荐」、label 里的无括号写法或 `recommended: true`，界面统一按 label 末尾的「（推荐）」画徽标；标了推荐的选项在用户没动过那题时就是选中态。
- **题号并入标题**：可选参数 `number`（如 `"Q2"`）由界面并进 `header`，格式 `<number> · <header>`；`header` 已经以该题号开头就原样送出。
- **正文只写共用背景**：可选参数 `detail` 按 markdown 渲染在题干下方，只写各选项共用的背景；某个选项自己的取舍写进它自己的 `description`。
- **导入输入框，用户自己发送**：表单底部只有窄的导入键与「从这里分叉」。导入键把作答写进原生草稿，三种状态由草稿与当前作答算出来——「导入输入框」/「已导入」（打勾）/「更新输入框」，没有可导的作答时置灰并说明「先在上面勾选或自填」；发送权只在原生输入框的发送键上。
- **作答按实发消息回显**：这条调用之后有过用户发言，表单就**冻结**成提交时的样子（选择器与自填框锁住、文字还能选中）并按**实发消息**重画；消息里根本没有作答块时如实显示「本轮没有通过表单作答」，只有块坏了才退回本地那份。冻结后整块不折叠、始终摊开，顶上只多一行摘要。
- **从这里分叉**：按**本轮结束点**分叉出一条新会话并直接打开它，子会话那边是一张全新的、可填的表；分叉失败时按键当场变成「分叉失败，请重试」。
- **勾选与自填按会话保存**：按会话与 `callId` 存进 `localStorage`，刷新后恢复；用户把某题清空也算一条记录，不会被当成脏数据丢掉。

## 特性

- **题型与选项数必须搭配**：单选、多选没给选项，自由题却给了选项，都就地拒绝；升级前那个可选开关 `multi_select` 不再认——只要它出现，这一轮就被退回让它删掉。
- **入参校验只拦表单表示不了的东西**：同一轮里重复的 id、空白题干、缺题型、选项数与题型不搭、空白选项 label、同一题里归一化后同名的两个选项、**展开正文里把选项又列了一遍**（那会让页面上出现两遍选项）——命中即就地拒绝；题干与选项的分工是引导，不做子串校验，选项名里的顿号与冒号照常放行（作答按「一项一行」回填，不按字符分拆）。总说明只报违规条数，规则由逐条 `violations` 自己说。
- **表单住在轮次尾部**：表挂在 `conversation.chat.turnTail` 上，与正文同处一层，不被这一轮的「工作过程」折叠吞掉（工具行必被折进过程区，住那儿得先展开才看得见）。页面上没有进度行，也不套卡片边框、背景、内边距与内部滚动；按 wire 工具名注册的那条工具行保留，但只在入参被拒时画违规清单、调用失败时说明失败——投出去的轮次它什么都不画。
- **冻结的三种来历分得开**：冻结那一刻从用户实际发出去的那条消息里读作答段，按「题号并入的标题 → 题干 → id」认题，每一项先按该题选项的展示文字精确匹配、匹配不上的并进自填。块在就以块为准，块里没出现的题就是没作答（推荐默认不会被勾回来）；块在但形态坏了才退回表单里最后那份（本地那份，含推荐默认）；根本没有块说明用户没走表单，只挂一行「本轮没有通过表单作答」。完全不发隐藏协议、不改用户消息的形态。
- **导入块只认一对标记**：只有 `【拷问作答】` 与 `【/拷问作答】` 之间那段算作答块，升级前写出去的旧标记不算——老轮次按「没作答」显示，草稿里残留的旧段不被替换、也不当已有块。导入文本是「标题一行 + 每项一行（行首 `- `）」，草稿里已有导入块就原地替换它，块外用户手打的字一个不动。
- **界面上没有常驻的导入提醒**：表单里只有题目、选项、自填、导入键与分叉键；没有输入框里的常驻提醒，也没有发送时的弹窗或发送键旁的提示（平台没有发送前的提交钩子）。导入键自己那三种状态是唯一的提示。
- **流式与失败不假装读懂**：参数还在流式传输（`argsRaw` 解析不出来）时工具行什么都不画；结果形状不认识或调用失败，工具行给失败说明；被拒画违规清单且不标记结束本轮。升级前那版没写 `type` 的老轮次，表单不再画出来。
- **两处对外依赖**：表能露在过程折叠之外，靠的是 `conversation.chat.turnTail` 这个公开槽位（核心包一改名单就可能失效）；浏览器半边另注入了会话服务与工作台服务（`sessions` / `uiWorkspace`）用于分叉——少声明一个，整条 entry 失败、插件从页面消失。
- **与 grilling 技能的分工按接缝划**：技能正文只讲方法论与问题措辞，工具用法的机械细节（字段语义、哪些写法会被拒、作答块的形态）全部以本工具自述为准——技能不随 npm 包发布，机械细节留在工具自述里就不必跟着协议漂。「一轮只投一次表单、投出即结束」既是工具的运行时自述、也是技能方法论的一部分。
- **形态与装配**：bundle + 客户端半边，装完即用、profile 侧不需要手写补丁；工具自述、装配行、开发副本与自检清单见 [DETAILS.md](./DETAILS.md)。

## 安装

```bash
dsh plugin --profile web add @lynn123411/dsh-grilling-form
```
