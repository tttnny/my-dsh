# @lynn123411/dsh-grilling-form

grilling 轮的逐题拷问工具：把整轮问题作为一张可交互表单投在对话流的轮次尾部，投出即结束本轮；用户在表单里勾选、自填，点表单底部的「导入输入框」写进原生输入框草稿，再按原生发送键发出，作答随后作为下一条用户消息到达。它不出文本、不阻塞、不接管输入框。

## 概述

一轮拷问的题目一次性投出来：表单挂在对话流的轮次尾部，与正文同处一层，不被这一轮的「工作过程」折叠吞掉。页面上没有进度行，也不给整张表套卡片壳；选项不描边、整行可点，有框的只有每题的自填框。

**三种题型**：`single`（单选，一题至多留一项）、`multi`（多选，可多可少可不选）、`free`（自由题，一个打字框）。题型可以漏写：有选项按多选、没选项按自由。题号与题型由插件画：每题前面是 `1.` `2.` 这样的序号，序号后面紧挨着这题画成了哪种题型（单选 / 多选 / 自由），跟序号同一档小灰字；它照的是页面上真的画出来的控件——没有选项就写自由，有选项时按声明的单选与多选分。

**两处补充说明**：题目可以带一句 `detail` 说明这题的背景，每个选项可以带一句 `description` 解释它的取舍或影响；两处都从行首或选项文字下方起、用小一号的灰字，长度不限、自动换行。题干、选项、补充说明都按 markdown 渲染（宿主的 `MarkdownText`，紧凑版排版），链接点得开、点链接不会顺带勾上那一项。

**推荐项一眼可辨**：模型推荐某个选项时把 `（推荐）` 或 `(Recommended)` 写在它的选项文字末尾，插件认出标记、剥干净文字、画上徽标，并在用户没动过那题时默认勾上；用户取消掉之后不会被勾回来。

**导入输入框，用户自己发送**：表单底部只有窄的导入键与「从这里分叉」。导入键把作答写进原生草稿，三种状态由草稿与当前作答算出来——「导入输入框」/「已导入」（打勾）/「更新输入框」；什么都没填也能导（导出的空块本身就是「我明确什么都没选」这一次作答），发送权只在原生输入框的发送键上。

**作答带这张表的身份**：拷问作答块的开头写着这张表自己的记号，反解只认自己的那一块；两张表、两个轮次之间不会互相认领。

**三种后果分得开**：自己的作答块到了就冻结成实发消息里的那份（锁住、选项区整体压暗、文字还能选中）；后面某一轮又投出一张更新的表（带 `replace: true`）就只剩一行「提问表单已被后面那张取代」；两样都没有就照旧可填——转向消息、聊别的事、答别的表都不锁它。

**不会挤两张表**：已经有一张表在等作答时，模型再调一次会被拦下并拿到旧表问了什么；它要么带 `replace: true` 重发一张来更新或作废旧表，要么等用户答完再问。

**从这里分叉**：按本轮结束点分叉出一条新会话并直接打开它，子会话那边是一张全新的、可填的表；分叉失败时按键当场变成「分叉失败，请重试」。

**勾选与自填按会话保存**：按会话与 `callId` 存进 `localStorage`，刷新后恢复；用户把某题清空也算一条记录，不会被当成脏数据丢掉。

**三个技能随包覆盖**：启用时把 `grilling`、`implement-spec`、`code-review` 三个技能换成随包发布的 DSH 适配版；停用插件就回到你安装的那份。

与原生 `ask_user_question` 是两件事：原生那条在输入框上方接管作答面板，默认阻塞等答案，留给一次简单确认；本插件只负责 grilling 轮的逐题拷问。

## 安装与开关

```sh
dsh plugin --profile web add @lynn123411/dsh-grilling-form
```

这条命令把包名写进 profile 的 `dependencies` 与 `dsh.profile.bundles`，包内 `cordis.patch.yml` 随之插入一条根层 `- id: tool-grilling-form` 行；这一条行同时做两件事——宿主半边在它下面注册 `grilling_form` 工具，而它本身又是 root loader entry，Web shell 据此服务本包的浏览器半边（客户端 bundle 只对 root loader 的 enabled entry 服务）。profile 侧不需要任何手写补丁。

```yaml
- insert:
    - id: tool-grilling-form
      name: '@lynn123411/dsh-grilling-form'
```

工具在**根层**：注册进全局层后，profile 里每一个 preset 的 agent 都看得见它（子 scope 继承全局层；preset 自己同名的行会盖过全局那条，所以不需要幂等补丁）。代价是「所有 preset 都看得见」——preset 若要在模型可见目录里没有它，只能自己用 `ctx.tools.restrict` 把工具从本 scope 的可见集合里滤掉（或改成注册时带 `when` 条件），工具本身照旧注册。

停用插件即停用工具与表单渲染；随包技能覆盖同时退场，预设层那份回来。

升级过来的 profile 若还留着旧装配那条手写的 `- id: tool-grilling-form` 行，先删掉它，再 `dsh plugin remove`：留着不影响启动（同一 id 的两行会被 loader 按 id 合成一条，包不会被挂两遍），但 `dsh plugin remove` 只摘包与 `dsh.profile.bundles` 条目、不动 profile patch，那行会在卸载后变成悬空行，下次启动报 `failed to import` / `1 entry did not activate`，管理器的 `removeBundle` 还会因它仍活着而拒删（`bundle-in-use`）。

## 配置

**没有配置项**：这条装配行不写 `config`，写了当场抛（`src/index.js` 的 `assertNoConfig`），免得拼错的行静默什么都不注册。

表单本身的「可调项」全在工具入参里，由模型按每次拷问填：`questions` / `questions[].question`（必填）/ `questions[].detail` / `questions[].type` / `questions[].options` / `questions[].options[].label`（必填）/ `questions[].options[].description` / `replace`，输出 `{ ok, message }`。每条描述只说这个字段填什么——默认值、兜底与校验规则由插件自己办，不占模型的注意力。

勾选与自填按会话持久化在浏览器侧：键 `dsh-grilling-form.<sessionId>`，按 `callId` 存；storage 不可用或写不进去只让这一份活在内存里。两处补充说明（题目的 `detail`、选项的 `description`）只负责显示，不参与选项身份、不进作答块，也不存进 `localStorage`。

## 实现

### 装配

一条 insert 行承载两个半边：宿主半边注册 `grilling_form` 工具并维护闸门，浏览器半边注册表单渲染（`conversation.chat.turnTail`）与工具行（`tool.call.toolview`，key `grilling_form`）。浏览器半边另注入了会话服务与工作台服务（`sessions` / `uiWorkspace`）用于分叉——少声明一个，整条 entry 失败、插件从页面消失。

### 工具与闸门

一次调用做三件事：校验入参；读闸门；通过就 `exec.concludeTurn()` 标记本轮结束，并返回 `{ ok: true, message }`，让模型知道表单已展示、答案会晚到、别把这次调用当成已回答、也别再把题目写一遍散文。

**闸门：同一时刻至多一张待答的表**。状态是会话投影里的一个单元（`src/form-model.js` 的 `FORM_GATE_UNIT`，键 `grillingFormPending`）：这次调用的开始事件先把这次调用记成候选，它的结算事件说 `ok: true` 才算真的有一张待答的表（`ok: false` 只丢掉候选，前一张待答的表一个不动），用户发言里出现这张表的身份记号就清空。两种呈现模式各是一类事件，折叠都认：原生是 `tool/call` + `tool/result`（身份 `callId`），PTC 是子调用的 `tool/ptc-dispatch-start` + `tool/ptc-dispatch`（身份 `subCallId`，参数是摊开的对象而不是 JSON 文本）。两个槽位必须分开：读闸门发生在调用事件之后、结果事件之前，那时新调用已经进了候选槽位，而它有没有真的投出去还不知道。

宿主半边不读会话的事件日志，只注册投影单元并在执行时读它。投影是可选依赖：注册走 `ctx.inject(['sessionProjections'], ...)`，服务比本插件晚挂上时 cordis 会重跑那段回调把单元补上；服务缺席的组合里这一层退化成不拦，工具照常注册。结果形状认不出「投出去了」（`rejected` / `pending` 那些）的调用进不了待答槽位，闸门不会被它卡死。

### 入参校验

只拦表单表示不了的三件事：空白题干、空白选项文字、同一题里去掉推荐标记后同文的两个选项（那会让用户选的东西在回填时落到另一项上）。其余一律交给兜底与宿主：漏写题型按「有选项多选、没选项自由」兜底；题型与选项不搭、老开关 `multi_select`、重复 id 都不再拒收；`questions` 不是数组、缺字段、题型不在三个取值里，由 `defineTool` 的入参校验拦住。

入参被校验拦下时抛 `ToolArgsError`（错误码 `INVALID_ARGS`，说明就是那几条违规、一条一行），这一轮不结束，模型可在同一轮改完重调；已经有一张表在等作答、又没带 `replace: true` 时返回 `{ ok: false, message }`，既不投出也不结束。

### 表单渲染

表挂在 `conversation.chat.turnTail` 上——与正文同处一层，不被这一轮的「工作过程」折叠吞掉（工具行必被折进过程区，住那儿得先展开才看得见）。可填时不画折叠行，也不套卡片边框、背景、内边距与内部滚动。按 wire 工具名注册自有 key `grilling_form` 的那条工具行保留，但只在没投出时画那句说明（入参被拒或被闸门拦下都是它）、调用失败时说明失败——投出去的轮次它什么都不画。

每个选项是一整行可点的行：里面依次是视觉上藏起来的原生 `<input type="checkbox">`（开关状态与禁用由它决定）、插件画的圈（单选）或方框（多选），以及选项文字与它的补充说明。整行点击也切换这一项，但落在链接或按钮上的那次不切换。圈与方框 16×16、跟文字第一行对齐；方框选中时填品牌色并画一个勾，圈选中时里面一个实心点。选中不动文字颜色与底色——勾选状态只由控件本身表达。不把整行包成 `<label>`：`<label>` 只收行内内容，而选项文字与补充说明都是 markdown 渲染器给的块级元素。

三种题型的页面：单选是圈里一个实心点的选项行，一题至多留一项，再勾一个就换掉上一个、再点一下是取消；多选是方框加勾，可多可少可不选；单选与多选底下另有一个自填框（「选项不够用的话，在这里自己写一段」），自由题没有选项行，只有一个输入框，比别处高、框里不写提示文字。三种题型每道题都有那个补充框。

表单在 `MarkdownDelegateProvider` 里渲染，槽位给的 `openFile` 传下去，所以本地文件链接点得开。紧凑版自带 13px 字号与灰色，正文两处（题干、选项文字）由外层改回 14px 与主文字色，补充说明保持紧凑版原样。

### 作答块协议

起止行是 `【拷问作答 <记号>】` / `【/拷问作答】`，记号取调用 id 里的小写字母数字 4 位（`shortFormId`，插件生成，用户不用管也不用记）。PTC 子调用的 id 是 `<父调用 id>:ptc:<序号>`：去掉 `ptc` 这三个字符，父调用 id 与序号一起参与取号——只留序号会让两轮的第一张表撞记号，只留父调用 id 会让同一个 `run_code` 里连派的几张撞记号。

块里每题一段：第一行只有题号（`1.`），其后每项一行（行首 `- `）；不写题干。多行自填按行拆成多个项行，反解把相邻的项行用换行拼回同一段——于是块里只许有这两种行，多一句说明就算块坏了。空作答就是只有起止行的空块。

反解要求起止行配对且记号相符：别的表的块、不带记号的那种块（`【盘问作答】`）都不算作答块；冻结与闸门按同一个判据，只有开头那行的半截文本不算作答。

### 三种后果

- **冻结**：自己的作答块到了，按那条发言重画，锁住、文字还能选中、选项区整体压暗。块里没出现的题就是没作答（推荐默认不会被勾回来）；块在但一条题号都认不出来（形态坏了）才退回本地那份，内容不凭空消失。冻结之后不折叠、始终摊开：顶上只多一行摘要（「本轮已过 · N 题 · 已填 M」，带问号图标），它只是文字、不是开关。
- **被取代**：这张表后面某一轮投出过一张带 `replace: true` 的表时，它只剩那一行字——题面、选项、自填框、导入键、分叉键都不再画。已经答过的表不显示这一行。取代时搬的是勾选：新表上题干原文一模一样的题带着旧表的勾选与自填（改一个字就不搬；勾选只留新表还认得的那几项）；草稿一律由用户按键才动。
- **可填**：判据是块到没到，不是「点了导入」也不是「发了消息」——转向消息、聊别的事、答别的表都不锁它。

冻结的压暗范围：选项文字、选项的补充说明、推荐徽标与自填框压到 0.5 透明；勾选框的圈与方框、题干、题号、题型、题目的补充说明都不压——回看时题目照样读得清，勾了哪一项也一眼看得出。

### 导入与分叉

没有提交键：表单底部只有窄的导入键与「从这里分叉」。「导入输入框」把作答写进原生草稿（槽位标准属性 `inputActions.setDraft`），发送权只在原生输入框的发送键上，插件不代发。导入键的三种状态由草稿与当前作答算出来：草稿里还没有这块 ⇒「导入输入框」；块正好是当前这份作答 ⇒「已导入」（打勾图标，再点只是重复写同一份）；表单改过之后块就旧了 ⇒「更新输入框」。只要还没冻结按键就能按——一项作答都没有也照导，导出去的是一块只有起止行的空块。草稿里已有这张表的块就原地换掉它，块外用户手打的字一个不动，别的表的块也不动；没有块就放在最前面。

界面上没有常驻的导入提醒，也没有发送时的弹窗或发送键旁的提示（平台没有发送前的提交钩子，发送不会因为没导入而被提示或拦下）。导入键自己那三种状态是唯一的提示。

「从这里分叉」按本轮结束点分叉出一条新会话并直接打开它；分叉失败时按键当场变成「分叉失败，请重试」。

### 技能覆盖

`skills/grilling/SKILL.md`、`skills/implement-spec/SKILL.md`、`skills/code-review/SKILL.md` 是三个技能的中文 DSH 适配版。插件读取各技能的 `SKILL.md`，许可随正文放在 `skills/LICENSE`。

预设把 `skill-filesystem` 挂在 preset 层，注册表先合并全局层、再按 scope 链覆盖，近的层直接赢，rank 只在同一层里比；根层注册的 rank 0 也压不过 preset 层。所以 provider 在 `agent/created` 时通过 `agent.ctx` 挂进 agent 层（比 preset 更近），插件比 agent 晚挂上时用 `agents.list()` 补一遍。`skills` 服务缺席时跳过这个 agent，工具照常注册；每个 provider 的卸载句柄按 agent 记在插件里，`agent/disposed` 与插件卸下都调用它，预设层那份回来。

frontmatter 只认子集：首行 `---` 到下一个 `---`；`name`、`description`（带引号走 JSON、不带引号取整行）、`disable-model-invocation`、`user-invocable`（`true/false/yes/no/1/0`）；正文 `trim()`。缺 name/description、name 不是 kebab-case、name 与目录名不一致时直接抛，插件装载失败。

### 流式与失败

参数还在流式传输（`argsRaw` 解析不出来）时工具行什么都不画（表在这一轮结束时出现在尾部）；调用失败时工具行给失败说明。结果形状认不出来（`rejected` / `pending` 那些）时两个注册项都什么都不画——轮次里没有可画的表，工具行也没有可说的话。

## 模型体验

`grilling_form` 的 `description` 与字段说明就是模型看到的全部机械细节（字段语义、推荐约定、作答块形态），技能正文不重复这些。工具面是八个字段、十一条描述；每条描述只说这个字段填什么，默认值、兜底与校验规则一律不写进去——这些字模型每轮都要读一遍，写进去的规则只会让真正要填的那件事更难找。

模型推荐某个选项时写在它的 `label` 里（放在最前、文字以 `（推荐）` 或 `(Recommended)` 收尾）。`src/recommendation.js` 认出末尾的标记（圆括号、方括号、`；推荐` 这类无括号写法都认，中英文都认，连着写几段也一直剥到末尾不再是标记为止），把标记从文字里剥干净，界面另画「推荐」徽标。剥出来的那段文字同时是选项身份，导入文本与用户消息里不会跟着这个标记。没有任何独立的推荐字段。

投出后返回的那句说明告诉模型：表单已展示、答案会晚到、别把这次调用当成已回答、也别再把题目写一遍散文。

技能正文只讲方法论与问题措辞，工具用法的机械细节（字段语义、推荐约定、作答块的形态）全部以本工具自述为准——技能正文与工具自述的接缝一起验。「一轮只投一次表单、投出即结束」既是工具的运行时自述、也是技能方法论的一部分。

## 限制

- **表能露在过程折叠之外，靠的是 `conversation.chat.turnTail` 这个公开槽位**：核心包一改名单就可能失效。
- **工具在全局层**：profile 里每个 preset 的 agent 都看得见它，收窄只能由 preset 自己 `restrict`。
- **平台没有发送前的提交钩子**：导入与否不会被拦下或提示，发送权完全在原生输入框的发送键上。
- **记号只取 4 位**：两张表撞记号需要它们的调用 id 末 4 位恰好相同。
- **块里只许有两种行**：多一句说明就算坏块，反解退回本地那份。
- **技能覆盖依赖 `skills` 服务**：服务缺席时这一层不注册，工具照常注册。
