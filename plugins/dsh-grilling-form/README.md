# @lynn123411/dsh-grilling-form

grilling 轮的逐题盘问工具：把整轮问题作为一张**可交互表单**投在对话流的**轮次尾部**（没有折叠行、没有卡片壳，跟正文同处一层）投出即结束本轮；用户在表单里勾选、自填，点表单底部的「导入输入框」写进**原生输入框草稿**，再按原生发送键发出，作答随后作为**下一条用户消息**到达。它不出文本、不阻塞、不接管输入框，与原生 `ask_user_question`（[`@deepseek-ai/dsh-tool-ask-user`](https://www.npmjs.com/package/@deepseek-ai/dsh-tool-ask-user)）是两件事：原生那条在输入框上方接管作答面板、阻塞等答案，留给一次简单确认；本插件只负责 grilling 轮的逐题盘问。

## 功能

- **`grilling_form` 工具**：一次调用校验入参、标记本轮结束（`exec.concludeTurn()`）、返回 `{ ok: true, message }`，让模型知道表单已展示、答案会晚到；投出即结束，不等待答案、不接管输入框。入参不合格则返回 `{ ok: false, message }` 且**不标记结束**，模型可在同一轮改完重调。
- **三种题型**：`single`（单选，一题至多留一项）、`multi`（多选，可多可少可不选）、`free`（自由题，一个打字框）。题型可以漏写：有选项按多选、没选项按自由。
- **题号由插件画**：每题前面是 `1.` `2.` 这样的序号，照着编号作答即可；作答块里也只记编号，不抄题干。
- **两处补充说明**：题目可以带一句 `detail` 解释这道题问什么，每个选项也可以带一句解释它的取舍或影响；两处都从行首或选项文字下方起、用小一号的灰字，长度不限、自动换行。没写就不显示，也不校验。
- **题干、选项、补充说明按 markdown 渲染**：模型写的粗体、行内代码、链接都生效（宿主的 `MarkdownText`，紧凑版排版），链接点得开、点链接不会顺带勾上那一项。
- **每个选项是一块可点的框**：勾选框、选项文字、推荐徽标与它的补充说明都在里面，整块点一下就是勾选；三种题型都另有一个补充框。
- **推荐项一眼可辨**：模型推荐某个选项时把「（推荐）」写在它的选项文字末尾，插件认出标记、剥掉文字、画上徽标，并在用户没动过那题时默认勾上；用户取消掉之后不会被勾回来。
- **更新的表会接过旧表的作答**：后面那张带 `replace: true` 的表把旧表顶掉时，题干一字不差的那些题带着旧表的勾选与自填，草稿里旧表那块也整段换成新表那块。
- **导入输入框，用户自己发送**：表单底部只有窄的导入键与「从这里分叉」。导入键把作答写进原生草稿，三种状态由草稿与当前作答算出来——「导入输入框」/「已导入」（打勾）/「更新输入框」；什么都没填也能导（导出的空块本身就是「我明确什么都没选」这一次作答），发送权只在原生输入框的发送键上。
- **作答带这张表的身份**：导入块的开头写着这张表自己的记号，反解只认自己的那一块；两张表、两个轮次之间不会互相认领。
- **三种后果分得开**：自己的作答块到了就**冻结**成实发消息里的那份（锁住、选项区整体压暗、文字还能选中）；后面某一轮又投出一张更新的表（带 `replace: true`）就只剩一行「提问表单已被后面那张取代」；两样都没有就照旧可填——转向消息、聊别的事、答别的表都不锁它。冻结后整块不折叠、始终摊开，顶上只多一行摘要。
- **不会挤两张表**：已经有一张表在等作答时，模型再调一次会被拦下并拿到旧表问了什么；它要么带 `replace: true` 重发一张来更新或作废旧表，要么等用户答完再问。
- **从这里分叉**：按**本轮结束点**分叉出一条新会话并直接打开它，子会话那边是一张全新的、可填的表；分叉失败时按键当场变成「分叉失败，请重试」。
- **勾选与自填按会话保存**：按会话与 `callId` 存进 `localStorage`，刷新后恢复；用户把某题清空也算一条记录，不会被当成脏数据丢掉。补充说明（`detail`）只负责显示，不参与选项身份、不进作答块，也不存进 `localStorage`。

## 特性

- **工具面是八个字段、十一条描述**：`questions` / `questions[].question`（必填）/ `questions[].detail` / `questions[].type` / `questions[].options` / `questions[].options[].label`（必填）/ `questions[].options[].detail` / `replace`，输出 `{ ok, message }`。每条描述只说这个字段填什么——默认值、兜底与校验规则由插件自己办，不占模型的注意力。
- **入参校验只拦表单表示不了的东西**：空白题干、空白选项文字、同一题里去掉推荐标记后同文的两个选项（那会让用户选的东西在回填时落到另一项上）。其余一律交给兜底与宿主：`questions` 不是数组、缺字段、题型不在三个取值里，由 `defineTool` 的入参校验拦住。总说明就是那几条违规，一条一行。
- **闸门靠会话投影维护**：待答的那张表记在一个会话投影单元里（`tool/call` 记下候选、它的结果说投出去了才算数、用户发言里出现这张表的记号就清空），执行时同步读；宿主半边不读会话的事件日志。注册走 `ctx.inject`（服务晚挂上时 cordis 会补注册），服务缺席的组合里这一层退化成不拦，工具照常注册。
- **表单住在轮次尾部**：表挂在 `conversation.chat.turnTail` 上，与正文同处一层，不被这一轮的「工作过程」折叠吞掉（工具行必被折进过程区，住那儿得先展开才看得见）。页面上没有进度行，也不给整张表套卡片壳；有框的只有选项——每个选项是一块 0.5px 描边的圆角行，整块可点。按 wire 工具名注册的那条工具行保留，但只在没投出时画那句说明、调用失败时说明失败——投出去的轮次它什么都不画。
- **作答块只认一对带记号的标记**：起止行是 `【拷问作答 <记号>】` / `【/拷问作答】`，记号取调用 id 里的 4 位；块内每题一段，第一行只有题号（`1.`）、其后每项一行（行首 `- `），不写题干。多行自填按行拆成多个项行，反解再拼回同一段——于是块里只许有这两种行，多一句说明就算块坏了。空作答就是只有起止行的空块。记号对不上、或者不带记号的那种块（`【盘问作答】`）都不算这张表的作答；结果形状认不出来的轮次，两个注册项也都不画它。
- **冻结按实发消息重画**：从用户实际发出去的那条消息里读这张表的作答块，按题号对回题序（题干重复或被改写都不影响回填）；块里没出现的题就是**没作答**（推荐默认不会被勾回来）；块在但一条题号都认不出来（形态坏了）才退回本地那份，内容不凭空消失。完全不发隐藏协议、不改用户消息的形态。冻结时选项区（选项文字、选项的补充说明、推荐徽标、自填框）整体压到 0.5 透明，勾选框的圈与方框保持原色，题干与题号不压。
- **导入块就地替换**：草稿里已有这张表的块就原地换掉它，块外用户手打的字一个不动，别的表的块也不动；没有块就放在最前面。
- **界面上没有常驻的导入提醒**：表单里只有题目、选项、自填、导入键与分叉键；没有输入框里的常驻提醒，也没有发送时的弹窗或发送键旁的提示（平台没有发送前的提交钩子）。导入键自己那三种状态是唯一的提示。
- **流式与失败不假装读懂**：参数还在流式传输（`argsRaw` 解析不出来）时工具行什么都不画；调用失败时工具行给失败说明。
- **两处对外依赖**：表能露在过程折叠之外，靠的是 `conversation.chat.turnTail` 这个公开槽位（核心包一改名单就可能失效）；浏览器半边另注入了会话服务与工作台服务（`sessions` / `uiWorkspace`）用于分叉——少声明一个，整条 entry 失败、插件从页面消失。
- **与 grilling 技能的分工按接缝划**：技能正文只讲方法论与问题措辞，工具用法的机械细节（字段语义、推荐约定、作答块的形态）全部以本工具自述为准——技能不随 npm 包发布，机械细节留在工具自述里就不必跟着协议漂。「一轮只投一次表单、投出即结束」既是工具的运行时自述、也是技能方法论的一部分。
- **形态与装配**：bundle + 客户端半边，装完即用、profile 侧不需要手写补丁；工具自述、装配行、开发副本与自检清单见 [DETAILS.md](./DETAILS.md)。

## 安装

```bash
dsh plugin --profile web add @lynn123411/dsh-grilling-form
```
