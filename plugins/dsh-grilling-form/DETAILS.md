## 工具自述

`grilling_form` 的 `description` 与字段说明就是模型看到的全部机械细节（字段语义、推荐约定、作答块形态），技能正文不重复这些。

- **工具面是八个字段、十一条描述**：`questions` / `questions[].question`（必填）/ `questions[].detail` / `questions[].type` / `questions[].options` / `questions[].options[].label`（必填）/ `questions[].options[].detail` / `replace`；输出 `{ ok, message }`。每条描述只说这个字段填什么，默认值、兜底与校验规则一律不写进去——这些字模型每轮都要读一遍，写进去的规则只会让真正要填的那件事更难找。
- **一次调用做三件事**：校验入参；闸门；通过就 `exec.concludeTurn()` 标记本轮结束，并返回 `{ ok: true, message }`，让模型知道表单已展示、答案会晚到、别把这次调用当成已回答、也别再把题目写一遍散文。入参不合格返回 `{ ok: false, message }`（那几条违规一条一行）且**不标记结束**，模型可在同一轮改完重调。
- **闸门：同一时刻至多一张待答的表**。会话里已经有一张表在等用户作答时，再调一次会被拦下——不投出、不结束本轮，说明里抄着旧表问了什么，并给出两条出路（同一批问题要更新或作废旧表就带 `replace: true` 重发；与旧表无关就停手，等用户答完再问，别把两批问题写进散文挤在一起）。
  状态是会话投影里的一个单元（`src/form-model.js` 的 `FORM_GATE_UNIT`，键 `grillingFormPending`）：`tool/call` 先把这次调用记成候选，它的 `tool/result` 说 `ok: true` 才算真的有一张待答的表（`ok: false` 只丢掉候选，前一张待答的表一个不动），用户发言里出现这张表的身份记号就清空。两个槽位必须分开：读闸门发生在调用事件之后、结果事件之前，那时新调用已经进了候选槽位，而它有没有真的投出去还不知道。清空认的是**配对的块**（起止行都在、记号相符），只有开头那行的半截文本什么都没答。宿主半边不读会话的事件日志（`Session.eventAt` / `snapshotEvents` / `ownEvents` 已封给新调用），只注册投影单元并在执行时读它。投影是**可选依赖**：注册走 `ctx.inject(['sessionProjections'], ...)`，服务比本插件晚挂上时 cordis 会重跑那段回调把单元补上，注册的收尾挂在这个子上下文上；服务缺席的组合里这一层退化成不拦，工具照常注册。结果形状认不出「投出去了」（`rejected` / `pending` 那些）的调用进不了待答槽位，闸门不会被它卡死。
- **入参校验只拦表单表示不了的三件事**：空白题干、空白选项文字、同一题里去掉推荐标记后同文的两个选项。选项身份就是那段文字（界面照它存勾选、导入文本照它写回），同文即无从分辨用户选的是哪一个，所以就地拒绝。其余一律交给兜底与宿主：漏写题型按「有选项多选、没选项自由」兜底；题型与选项不搭、老开关 `multi_select`、重复 id 都不再拒收；`questions` 不是数组、缺字段、题型不在三个取值里，由 `defineTool` 的入参校验拦住（直接调 `validateRound` 时它交回空清单而不是抛异常）。
- **题型三种，缺省有兜底**：`single`（单选）/ `multi`（多选）/ `free`（自由）。三者的页面：单选是圈里一个实心点的选项行，一题至多留一项，再勾一个就换掉上一个、再点一下是取消；多选是方框加勾，可多可少可不选；单选与多选底下**另有一个自填框**（「选项不够用的话，在这里自己写一段」，常常是对选项的补充）；自由题没有选项行，只有一个输入框，比别处高（约 4 行）、框里不写提示文字。**三种题型每道题都有那个补充框**。界面上不写题型，看形状就够。
- **每个选项是一块可点的框**：整行是一个容器，里面依次是视觉上藏起来的原生 `<input type="checkbox">`（开关状态与禁用由它决定）、插件画的圈（单选）或方框（多选），以及选项文字与它的补充说明。整行点击也切换这一项，但落在链接或按钮上的那次不切换（那是跳转）。圈与方框 16×16、跟文字第一行对齐；方框选中时填品牌色并画一个勾，圈选中时里面一个实心点。选中不动文字颜色与底色——勾选状态只由控件本身表达。**不把整行包成 `<label>`**：`<label>` 只收行内内容，而选项文字与补充说明都是 markdown 渲染器给的块级元素。
- **序号由插件画**：题号按题目次序从 1 起，与题干同处一行（`1. 题干`，题号占一列、与题干顶端对齐）。作答块里也只记这个号，所以**块里不写题干**——反解按题号对回题序，题干重复或被改写都不影响回填。题干之外不再有标题。
- **两处补充说明**：题目可带 `detail`（题干下方单独一行、从行首开始），每个选项可带 `detail`（缩进到选项文字下方）；两处都是小一号的灰字，长度不限、自动换行。`detail` 去掉首尾空白，空白与不是字符串都算没写（模型漏写不会整轮被拒）；它**只负责显示**——不参与选项身份、不参与同文校验、不参与取代时按题干配对的搬运，也不进作答块与 `localStorage`。
- **题干、选项文字与两处补充说明都按 markdown 渲染**：用宿主的 `MarkdownText`（紧凑版），粗体、行内代码、链接、列表都生效，原始 HTML 被渲染器丢弃、非 http(s) 链接不生效。表单在 `MarkdownDelegateProvider` 里渲染，槽位给的 `openFile` 传下去，所以本地文件链接点得开；链接落在选项这一行的 `<label>` 里，点链接不会顺带勾上那一项。紧凑版自带 13px 字号与灰色，正文两处（题干、选项文字）由外层改回 14px 与主文字色，补充说明保持紧凑版原样。
- **推荐写进选项文字**：模型推荐某个选项时写在它的 `label` 里（放在最前、文字以「（推荐）」收尾），`src/recommendation.js` 认出末尾的标记（圆括号、方括号、`；推荐` 这类无括号写法都认），把标记从文字里剥掉，界面另画「推荐」徽标。剥出来的那段文字同时是**选项身份**，导入文本与用户消息里不会跟着「（推荐）」。没有任何独立的推荐字段：推荐只由选项文字说了算，选项上多带的 `recommended` / `description` 一律不进模型（两条并存的写法里总有一条会漂）。
- **推荐项默认勾上**：标了推荐的选项在用户没动过那题时就是选中态；用户动过那题（包括把默认项取消掉）一律以他的为准，「取消过」与「没作答」分得开，靠的是持久化里那条空记录不会被清掉。
- **表单住在轮次尾部**：表挂在对话流的 `conversation.chat.turnTail` 上——与正文同处一层，不被这一轮的「工作过程」折叠吞掉。可填时不画折叠行，也不套卡片边框、背景、内边距与内部滚动；页面上没有进度行。按 wire 工具名注册自有 key `grilling_form` 的那条工具行**保留**，但只在没投出时画那句说明（入参被拒或被闸门拦下都是它）、调用失败时说明失败——投出去的轮次它什么都不画。表单本身是整轮题目——题号、题干、选择器（推荐项带徽标）与每题一个 textarea。
- **没有提交键**：表单底部只有窄的导入键与「从这里分叉」，「导入输入框」把作答写进原生草稿（槽位标准属性 `inputActions.setDraft`）；发送权只在原生输入框的发送键上，插件不代发。
- **作答块带这张表的身份记号**：起止行是 `【拷问作答 <记号>】` / `【/拷问作答】`，记号取调用 id 里的小写字母数字 4 位（`shortFormId`，插件生成，用户不用管也不用记）。块里每题一段：第一行只有题号（`1.`），其后每项一行（行首 `- `）；不写题干。多行自填按行拆成多个项行，反解把相邻的项行用换行拼回同一段——于是块里只许有这两种行。空作答就是只有起止行的空块；**块内多一句说明文字就算块坏了**，退回本地那份。反解要求起止行配对且记号相符：别的表的块、不带记号的那种块（`【盘问作答】`）都不算作答块；冻结与闸门按同一个判据，只有开头那行的半截文本不算作答。**只认这张表自己的块**，所以两张表、两个轮次之间不会互相认领。
- **导入键会说话**：草稿里还没有这块 ⇒ 「导入输入框」；块正好是当前这份作答 ⇒ 「已导入」（打勾图标，再点只是重复写同一份）；表单改过之后块就旧了 ⇒ 「更新输入框」。只要还没冻结按键就能按——一项作答都没有也照导，导出去的是一块只有起止行的空块，「我明确什么都没选」因此也能作为一次作答提交出去——空作答导出去之后按键就显示「已导入」，不会再催他更新。
- **拷问作答块就地替换**：草稿里已有这张表的块就原地换掉它，块外用户手打的字一个不动，别的表的块也不动；没有块就放在最前面。
- **三种后果分得开**：它自己的作答块到了 ⇒ **冻结**（按那条发言重画，锁住、文字还能选中、选项区整体压暗）；后面某一轮又投出过一张带 `replace: true` 的表 ⇒ 只剩一行「提问表单已被后面那张取代」；两样都没有 ⇒ 照旧可填。判据是**块到没到**，不是「点了导入」也不是「发了消息」——转向消息、聊别的事、答别的表都不锁它——正在填的表不会被一句转向消息冻住，也不会因为那条消息里没有块就被判成没作答。
- **冻结按实发消息重画**：从那条发言里读这张表的作答块，块里没出现的题就是**没作答**（推荐默认不会被勾回来）；块在但一条题号都认不出来（形态坏了）才退回本地那份，内容不凭空消失。冻结之后**不折叠、始终摊开**：顶上只多一行摘要（「本轮已过 · N 题 · 已填 M」，带问号图标），它只是文字、不是开关。没有自己的块就不冻结，表照旧等他作答。
- **冻结的压暗范围**：选项文字、选项的补充说明、推荐徽标与自填框压到 0.5 透明；勾选框的圈与方框、题干、题号、题目 detail 都不压——回看时题目照样读得清，勾了哪一项也一眼看得出。
- **被取代**：这张表后面某一轮投出过一张带 `replace: true` 的表时，它只剩那一行字——题面、选项、自填框、导入键、分叉键都不再画。已经答过的表不显示这一行（它是已答的那张，自作答块说了算）。取代发生的那一刻同时搬两件：新表上**题干原文一模一样**的题带着旧表的勾选与自填（改一个字就不搬；勾选只留新表还认得的那几项），草稿里旧表那块也整段换成新表那块、放在它原来的位置，用户自己手打的字一个不动。
- **界面上没有常驻的导入提醒**：没有输入框里的常驻提醒，也没有发送时的弹窗或发送键旁的提示（平台没有发送前的提交钩子，发送不会因为没导入而被提示或拦下）。导入键自己那三种状态是唯一的提示。
- **按会话持久化**：勾选与自填按会话 + `callId` 存进 `localStorage`（键 `dsh-grilling-form.<sessionId>`），刷新后恢复；一条「什么都没选」的记录也是记录（用户把这题清空了），不会被当成脏数据丢掉；storage 不可用或写不进去只让这一份活在内存里。
- **流式与失败不假装读懂**：参数还在流式传输（`argsRaw` 解析不出来）时工具行什么都不画（表在这一轮结束时出现在尾部）；调用失败时工具行给失败说明。结果形状认不出来（`rejected` / `pending` 那些）时两个注册项都什么都不画——轮次里没有可画的表，工具行也没有可说的话。
- **两处对外接口**：表能露在过程折叠之外，靠的是 `conversation.chat.turnTail` 这个公开槽位（核心包一改名单就可能失效）；浏览器半边另注入了会话服务与工作台服务（`sessions` / `uiWorkspace`）用于分叉——少声明一个，按仓库规则整条 entry 失败、插件从页面消失（见 `docs/rules/client-wiring.md`）。
- **与原生 `ask_user_question` 的分工**：原生那条管一次简单确认，本插件管 grilling 轮的逐题拷问。本工具与 https://github.com/tttnny/matt-skills-dsh 的 grilling 技能配合，分工按接缝划：**技能正文只讲方法论与问题措辞，工具用法的机械细节全部以本工具自述为准**。拷问作答块协议在 `src/form-model.js` 的常量旁留了一份「改协议时的联动点」清单（工具自述里的行形说法、四处自检里的字面量、两份 README、根 `GLOSSARY.md` 的词条、技能正文那句工具名），其中技能正文那一处没有任何测试看得见，只能靠清单提醒；新增写死协议字面量的测试或文档要补进那份清单。

## 装配形态

**装配是一条命令一行**：`dsh plugin --profile web add @lynn123411/dsh-grilling-form` 装完即用。命令把包名写进 profile 的 `dependencies` 与 `dsh.profile.bundles`，包内 `cordis.patch.yml` 随之插入一条根层 `- id: tool-grilling-form` 行；这一条行同时做两件事——宿主半边在它下面注册 `grilling_form` 工具（root 层 ⇒ 落进全局层，profile 里每个 preset 的 agent 都看得见），而它本身又是 root loader entry，Web shell 据此服务本包的浏览器半边（客户端 bundle 只对 root loader 的 enabled entry 服务）。**profile 侧不需要任何手写补丁。**

```yaml
- insert:
    - id: tool-grilling-form
      name: '@lynn123411/dsh-grilling-form'
```

- **工具**：宿主半边在这条行下注册 `grilling_form`。它在**根层**：注册进全局层后，profile 里每一个 preset 的 agent 都看得见它（子 scope 继承全局层；preset 自己同名的行会盖过全局那条，所以不需要幂等补丁）。**代价（明知并接受）**：全局层意味着「所有 preset 都看得见」——preset 若要在模型可见目录里没有它，只能自己在 `system-prompt/assemble` 处收窄，工具本身照旧注册。
- **浏览器半边**：这条行本身是 root loader **entry**，而客户端 bundle 只对 root loader 的 enabled entry 服务，Web shell 据此服务 `lib/client.js`。所以不需要额外的载体行——行本身既是工具行又是载体行。这一行**不写 `config`**：写了当场抛（`src/index.js` 的 `assertNoConfig`），免得拼错的行静默什么都不注册。

升级过来的 profile 若还留着旧装配那条手写的 `- id: tool-grilling-form` 行，**先删掉它，再 `dsh plugin remove`**：

- **留着不影响启动**：同一 id 的两行会被 loader 按 id 合成一条（`EntryGroup.update` 以 id 为键建 map），包不会被挂两遍，也不会报「already registered」。
- **但它会在卸载后变成悬空行**：`dsh plugin remove` 只摘包与 `dsh.profile.bundles` 条目，**不动 profile patch**，于是那行指向一个已不在的包，下次启动报 `failed to import` / `1 entry did not activate`（实例照常起，只是告警）。服务端与管理器的 `removeBundle` 还会因那行仍活着而直接拒删（`bundle-in-use`）。
- 所以：装完本包后那行就是多余的，删掉即可；要卸载这个插件时，**必须先删那行**。

验证（只组合、不装载）：

```bash
node "<DSH 安装>/node_modules/@deepseek-ai/dsh/lib/bin.js" --profile web --dump-config | grep -n tool-grilling-form
# 期望：命中本包 bundle 层那条插入行（且只有一条、不带 config）
```

## 开发副本

用 `link:`，不要拷贝——运行副本软链接到本仓库目录后，仓库里的文件就是「已安装内容」（细则见仓库 `docs/rules/dev-copy.md`）：

```bash
cd ~/.dsh/profiles/web && pnpm add "link:<my-dsh 绝对路径>/plugins/dsh-grilling-form" --offline
cd <my-dsh 绝对路径>/plugins/dsh-grilling-form && pnpm install && pnpm build
```

本插件宿主半边 `import` 了 `@deepseek-ai/dsh-tools`，浏览器半边 `import` 了 `@deepseek-ai/dsh-client-ui-primitives`；`link:` 插件的这些内核包由 DSH 自身路由供给（前提是 DSH 带 `--preserve-symlinks` 启动，启动器已默认带上）。**不要**手工拷贝进 `node_modules/`：裸拷贝是未注册状态，`pnpm install` / `dsh plugin add|remove` 等任何 profile 同步都会把它当 extraneous 清掉。

改完 `src/` 必须重新 `pnpm build`：宿主半边要触发一次 profile 重新组合才会换上新产物——在插件页或 `plugin_manager` 里把本插件关一次再开一次，不必重启进程；已经在图里的客户端 bundle 由 `dsh-client-hmr` 轮询到改动后热换，页面自行重载，必要时硬刷新一次。

## 自检

`pnpm check`（= `pnpm typecheck && pnpm test && pnpm assert:lib-untracked`）；`pnpm test` 自己先构建一次，所以改了 `src/` 忘了构建也不会静默测到旧产物（一半脚本打 `src/`、另一半打构建产物 `lib/`）：

- `tsc -p tsconfig.json --noEmit`（`allowJs` + `checkJs`，配置见包内 `tsconfig.json`）：源码是纯 JS，类型信息只有 JSDoc 一处。`src/form-model.js` 顶部那组 typedef（`Question` / `QuestionOption` / `Answer` / `AnswerTable` / `FormGate` / `StorageLike` 等）是题目模型、作答表与闸门状态在宿主半边、内壳、浏览器半边之间的共用类型；平台没发布类型的那些形状（chat 视图快照、槽位 props、客户端 cordis 上下文、会话投影服务）就地少量声明，不复制平台的影子类型。`scripts/*.mjs` 不在范围内；
- `scripts/test-recommendation.mjs`：推荐标记的识别——末尾的「（推荐）」与几种等价写法都认、剥掉标记后的文字就是选项身份（只差标记的两段文字归一化之后是同一个身份，宿主按同文选项把这一轮拒掉）、正常以「推荐」收尾的文字不误判；
